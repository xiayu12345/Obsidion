LQ140M1JW61 LCD + HDMI 双显排查 — 开发记录

| 项 | 内容 |

|---|---|

| 日期 | 2026-07-29 |

| 板型 | p1_nor_LQ140M1JW61 |

| 屏 | Sharp LQ140M1JW61 1920×1080（MIPI→eDP bridge lq140_mipi2edp） |

| 副屏 | HDMI 1080p（双显：DE0 合成 → 抓帧 → DE1/HDMI） |

| 结论 | LCD + HDMI 均正常、均不旋转（直出）；主因是 板级 DTS/env 配置未自洽或未真正生效，不是 dev_disp.c 必改 |

索引：../README.md

---

1. 结论（一句话）

双显出图异常（HDMI 全绿 → 偏绿横纹 / LCD 异常）排查后，回退 dev_disp.c 试验改动后仍正常，说明稳定点在 板级配置链路（DTS / env / 打包刷写一致性），而非 dual-display 驱动逻辑本身。LCD 当前为 软件直出（sunxifb_rot=0，dual_display_rot=0）。

---

2. 现象演进

| 阶段 | 现象 | 日志要点 |

|---|---|---|

| A | HDMI 无图、整屏绿 | 双显未稳定建立 / 缓冲或时序不足 |

| B | 有图但偏绿横纹；LCD/HDMI 不一致 | dual display enabled ... NV21 ... dual_display_rot=0 |

| C | 调参后 LCD 也曾异常 | 配置组合不自洽 |

| D | dual_display_rot=3 | LCD 正常，HDMI 被旋转 |

| E | dual_display_rot=0 + 配置一致 | LCD/HDMI 均正常、不旋转 |

| F | 回退 dev_disp.c 后再编再刷 | 仍正常 → 排除驱动试验改动为根因 |

---

3. 稳定态验收日志（关键）

[DISP] dual display HDMI G2D rot0: 1920x1080 full on 1920x1080 (WB 1920x1080)
[DISP] dual display enabled: 1920x1080 NV21, ... (dual_display_rot=0)
[desk] fb 1920x1080 -> LVGL 1920x1080, sunxifb_rot=0 tp_rotate=0

含义：

  • HDMI 双显路径：rot=0
  • desk / LCD 绘制：不做软件旋转（直出）

---

4. 排查过程（按时间）

4.1 板级资源与时序

  • 关注点：lcd_dclk_freq、cma、chn_cfg_mode、dual_display_rot
  • 过程中出现过「改了源文件，但启动日志仍是旧值」→ 打包/刷写/分区生效不一致

4.2 dual_display_rot 对照

| 值 | 结果 |

|---|---|

| 3 | LCD 正常；HDMI 旋转 |

| 0 | 目标态：LCD/HDMI 均不旋转；在配置自洽时可用 |

说明：0/3 在代码上都走 apply_rot，但 G2D/拷贝与几何不同；不能只凭「结构差不多」忽略参数差异与生效情况。

4.3 dev_disp.c 试验与回退（对照实验）

曾改 disp_dual_display_apply_rot()（rot=0 时 memcpy / G2D 顺序）。

| 步骤 | 结果 |

|---|---|

| 应用试验改动 | 现象反复，无法单独证伪/证实 |

| git checkout -- …/dev_disp.c 回退 | 重编 kernel 后刷机，LCD+HDMI 仍正常 |

→ 试验改动不是最终稳定条件。

4.4 仍保留的板级相关改动（非 dev_disp.c）

为新屏接入而存在、与「双显绿纹」根因正交的改动（面板编译入口等），例如：

| 类别 | 路径（示例） | 作用 |

|---|---|---|

| panel 注册 | kernel/u-boot disp/lcd/Kconfig、panels.c/.h、Makefile | LCD_SUPPORT_LQ140_MIPI2EDP / lq140_mipi2edp.o |

| OpenWrt target | openwrt/.openwrt_targets、各 defconfig | 增加 h133-p1_nor_LQ140M1JW61 |

| WB 旋转宏 | libtmedia/Makefile | LQ140M1JW61 走 VIDEO_WB_MIRROR_ROTATE=0 |

这些是新板编译/接入需要的，不要当成「绿屏根因补丁」误删。

---

5. 根因判断

| 判断 | 依据 |

|---|---|

| 主因：DTS/env 等板级配置未配齐或不一致生效 | 参数与启动日志曾对不上；rot 等切换后行为变化；其它板同驱动镜像正常 |

| 非主因：dev_disp.c 试验逻辑 | 回退后仍正常 |

| LCD 当前非软件旋转再出图 | sunxifb_rot=0、tp_rotate=0、dual_display_rot=0 |

8. 经验固化

  1. 双显异常先核对启动日志三件套是否与预期一致：cma、chn_cfg、dual_display_rot。
  2. 先保证 配置真正进镜像，再改 dev_disp.c。
  3. 驱动试验必须做 回退对照；回退后仍好 = 试验代码不是根因。
  4. 新屏 panel 编译入口与双显绿纹问题分开归档，勿混为一谈。
