# 双屏同/异显 — 合并后使用与构建

补丁已合进树。本文只讲**怎么用、怎么编**。设计过程见 [20260806](./20260806-同异显切换/)、头文件坑见 [20260828](./20260828-libuapi内核头对齐/)。

---

## 1. 行为

MIPI = screen0（LCD/UI），HDMI = screen1。WB 管道启动后常开，切模式**不拆** WB。

| 模式 | HDMI | 视频 | `disp_mode` |
|---|---|---|---|
| **同显 SAME**（默认） | WB 镜像 LCD | DE0 / LCD | `same` |
| **异显 DIFF** | 关掉 HDMI 上 WB 层 | DE1 / HDMI（须已插线） | `diff` |

未插 HDMI 时视频强制 LCD。播中切模式失败（`-EBUSY`）。切完要**再起播**才按新屏建层。偏好落 `/etc/disp_mirror_mode`，重启 `boot_sync` 再 apply。

不要在蓝牙 K 歌里测：异显后电视不再镜像 UI，看起来像界面没了。去点歌播一首。

---

## 2. 机上命令

```bash
disp_mode get
# hdmi=1 wb=1
# same: hdmi_out=1 video_screen=1
# diff: hdmi_out=0 video_screen=2

disp_mode same
disp_mode diff
```

插 HDMI → 停播 → `disp_mode diff` → 进点歌再播。LCD 应只剩 UI，视频在电视。

---

## 3. 应用接口（不必走命令）

链 `-luapi`，头文件 `/usr/include/disp_dual.h`：

```c
#include <disp_dual.h>

sunxi_disp_mode_t mode;
sunxi_disp_mode_get(&mode);
sunxi_disp_mode_set(SUNXI_DISP_MODE_DIFF);  /* 异显 */
sunxi_disp_mode_set(SUNXI_DISP_MODE_SAME);  /* 同显 */

sunxi_disp_hdmi_connected();        /* 0/1 */
sunxi_disp_video_screen_mask();     /* 1=LCD，DIFF+已插=2 */
```

产品路径只用 `sunxi_disp_mode_set` / `get`。不要单独调 `sunxi_dual_display_set_hdmi_output()`（那是只切 HDMI 上 WB 层）。桌面/设置页目前未接，要 UI 开关就调这套 API。

播中 `set` 返回 `-EBUSY`。

## 4. 构建注意事项

异显是**内核 ioctl + libuapi 结构体**成对的。只编一边会对不齐，`SET_CONFIG2` 会把栈当 `layer_id` Oops。

### 4.1 头文件必须跟内核走

官方 libuapi 是 `#include <video/sunxi_display2.h>`，实际吃**工具链**头，不是 `headers_install`。

改过 `kernel/linux-5.4/include/video/sunxi_display2.h` 之后：

1. 覆盖工具链（glibc 必换；musl 一并换）：

```bash
K=kernel/linux-5.4/include/video/sunxi_display2.h
cp -a "$K" prebuilt/rootfsbuilt/arm/toolchain-sunxi-glibc-gcc-830/toolchain/include/video/sunxi_display2.h
cp -a "$K" prebuilt/rootfsbuilt/arm/toolchain-sunxi-musl-gcc-830/toolchain/include/video/sunxi_display2.h
```

2. **清 libuapi 再编用户态**，再 pack。不要只编内核。

不要：改内核结构迁就旧头、`-I` 整棵 `kernel/include`、给 libuapi 加 `kern_inc`、把 libuapi 改成 tinycedar 那种 `"sunxi_display2.h"`。

### 4.2 编哪几块

| 改了什么 | 要编 |
|---|---|
| 内核 disp / `sunxi_display2.h` | kernel（boot.img）**并且**换工具链头 + 重编 libuapi |
| `disp_dual.c` / libuapi | OpenWrt `libuapi` |
| `tlayer_ctrl.c` | `libtmedia` |
| `media_session.c` | `media_session` |
| 只测命令 | 有 `/usr/bin/disp_mode` 和匹配的 `libuapi.so` 即可 |

强制重编用户态示例（ZS）：

```bash
rm -rf out/h133/p1_nor_ZS101/openwrt/build_dir/target/libuapi
./build.sh openwrt_rootfs
./build.sh pack
```

其它板把路径里的板名换掉。确认 `libuapi.so` 时间晚于换头。

### 4.3 板件脚本

```bash
./tools/build_p1_nor_JL_M101.sh full    # 京龙
./tools/build_p1_nor_ZS101.sh kernel    # 只编内核+uboot，不 pack
```

- `kernel` 模式**不 pack**，要镜像再 `./build.sh pack`。
- **ZS101 不要用脚本的 `full` / `rootfs`（里面是 `m`，会编 SPL 失败）。** 内核用 `./tools/build_p1_nor_ZS101.sh kernel`，用户态用 `./build.sh openwrt_rootfs` + `./build.sh pack`。
- 京龙 `full` 可用（`m` + `p`）。
- OpenWrt 外层要用 SDK **make 4.1**（脚本已前置 `prebuilt/hostbuilt/make4.1`）。
- **禁止**在 WSL/x86 对 `desk` / `libuapi` / `tlayer` 源码树本地 `make` / `gcc -c`（会留下 x86 `.o`，交叉链接 arm 炸）。

### 4.4 板级差异（构建时就会编进去）

`libtmedia` 的 `VIDEO_WB_MIRROR_ROTATE`：

| 板 | 值 |
|---|---|
| `p1_nor` / `p1_nor_8733` / `p1_nor_JL_M101` | 90 |
| `p1_nor_JYY070` / `p1_nor_4k` | 0 |
| 其它（含 **ZS101**） | 默认 0 |

换板编 `libtmedia` 时看 Makefile 的 `CONFIG_TARGET_h133_*`，不要混 90/0 的包。

各板 `defconfig` 已是 `CONFIG_SUNXI_DISPLAY_TWO=y`、`CONFIG_SUNXI_TRANS_DISPBUF_FD=y`。

## 5. 串口里可忽略的

- `[DISP] dual display already enabled`：WB 已起来，正常。
- cedarc 扫 `libaw_mp3dec.so`：音频库当视频插件，忽略。
- `dma_buf_get failed, fd=0`：起层时 fd 还是 0，**不是头文件没对齐**。对齐失败是脏 `layer_id` + Oops。
