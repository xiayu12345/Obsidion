HDMI 异显最小验证 — 开发记录（历史 TEMP）

| 项 | 内容 |

| 范围 | 架构通路验证 |

| 验证板 | p1_nor_JL_M101 |

| 显示定稿（板级） | JL_M101 20260722 定稿 |

| 架构参考 | LV_DS-双屏异显中间件架构.md |

| 补丁 | patches/ |

| 结论 | TEMP 异显通路 + 流畅度均通过（历史对照）。产品切换见 20260806-同异显切换（WB 常开，勿再 TEMP 关 WB） |

---

1. 目标与结论

1.1 产品意图（后续接口）

  • 同显 / 异显由用户态显式接口切换，不自动随 play/stop 切。
  • 异显期望：HDMI 已插 → 视频只上 HDMI，LCD 无该视频层；未插 → 视频仍上 LCD。
  • 同显：WB 镜像 UI（及 DE0 上内容）。

1.2 本次范围（最小验证，TEMP）

不做完整 set_mode 状态机，只验证「关掉镜像后，视频能否直出 HDMI」且流畅。

| 验收项 | 结果 |

|---|---|

| 未播片：LCD 有 UI，HDMI 不再镜像整屏 UI | 通过 |

| 播片：视频只在 HDMI，LCD 无视频层 | 通过 |

| HDMI 全屏（非左半屏） | 通过（rect 跟 HDMI 物理分辨率） |

| HDMI 播片流畅 | 通过（2026-08-06；根因见 §6 fence 屏号） |

---

2. 现网同显 vs 本次异显通路

2.1 现网同显（改前）

LVGL / desk → fb0 → DE0（LCD）
视频层 → DE0
              ↓
         WB 抓 DE0 合成帧 →（dual_display_rot）→ DE1 → HDMI

另有兜底：sunxi_fb_pan_display 在 WB 未开 时调用 disp_fb_clone_to_screen(fb0→screen1)，仍会把 UI 镜像到 HDMI。

视频侧写死：tlayer_ctrl.c disp_screen = 1（只贴 DE0），靠 WB「看见」视频。

2.2 本次 TEMP 异显（改后）

LVGL / desk → fb0 → DE0（LCD）          ← 仅 UI
视频解码 NV21 → videoOutPort（disp_screen=2）→ DE1 视频层 → HDMI
HWC fence timeline / sync point → screen1（与送显一致）
  • 不经 WB，不经 fb_clone。
  • WB 在现网 dual_display 路径上只能抓 DE0 合成帧，不能改成「只抓视频层」；要 HDMI 只有片，必须视频层直贴 DE1。

3. TEMP 改动清单（源码仍带 TEMP 标记）

| 文件 | 改动 |

|---|---|

| kernel/.../disp/dev_disp.c | 启动 / HPD 不再 disp_dual_display_enable()；保留 chn_cfg_mode=1（勿掉进 fb_clone 的 else） |

| kernel/.../disp/dev_fb.c | disp_fb_clone_to_screen() 入口直接 return（关 WB 后 pan 兜底镜像） |

| platform/.../tlayer_ctrl.c | disp_screen = 2；LayerSetDisplayRect HDMI 全屏 override；fenceScreenId 跟 disp_screen（create/destroy timeline、createSyncPoint） |

3.1 为何必须同时关 WB 与 fb_clone

  1. 只关 WB → HDMI 仍有 UI（pan_display → disp_fb_clone_to_screen）。
  2. 只改 disp_screen=2 且仍开 WB → DE1 上视频层与 WB 层抢同一路，画面乱。

3.2 左半屏问题

上层（如 BluetoothPlayer）全屏仍用 setting.ini 的 video_screen_*=800×1280（LCD）。

HDMI 为 1080p（screen1_output_mode=10）。disp_screen==3 时才有 disp_dual_scale_win；==2 不会自动放大。

处理：LayerSetDisplayRect 在 disp_screen==2 时强制 0,0 + getScreenWidth×getScreenHeight（实机多为 1920×1080）。

3.3 fence 必须跟送显屏（卡顿根因）

原代码 createSyncTimeline(0) / createSyncPoint(0) / destroySyncTimeline(0) 写死 LCD；异显 HWC_SUBMIT_FENCE 却跟 disp_screen 走到 screen1 → ACQUIRE/SUBMIT 脱节 → 卡顿。

修复：fenceScreenId = layerFenceScreenId()（仅 bit1 → screen1）。

日志特征：

[DISP] TEMP skip auto-enable dual display ...
[HDMI-ONLY] TEMP video disp_screen=2 fenceScreen=1 (no WB), ...
[HDMI-ONLY] TEMP override rect ... -> 0,0 1920x1080 (HDMI)

4. 关键结论（写进记录，避免再绕）

| 问题 | 结论 |

|---|---|

| WB 能否只抓视频帧？ | 不能。现网 cptr 挂 mgr0，抓 DE0 合成结果 |

| disp_screen 含义 | 位掩码：1=screen0，2=screen1，3=两路都贴 |

| disp_screen 能否热切？ | 无现成 API；须在 LayerCreate/DispInit 前设好，或 deinit→改→init |

| 软件能否关 WB？ | 内核有 disp_dual_display_disable()，用户态尚未导出 ioctl；本次用编译期跳过 enable |

| 异显卡顿主因 | HWC fence 屏号写死 0，与 disp_screen=2 不一致（非 DE1 linebuf） |

| 用户可控同显/异显 | 后续补接口 + 互斥切换；本次未做 |

6. HDMI 视频卡顿 — 排查与闭环

6.1 DE1 linebuf 假说 — 已排除

| A/B | 做法 | 结果 |

|---|---|---|

| 压宽 | screen_win 宽≤1024 居中 | 卡顿无好转 |

linebuf 约束仍真实存在（黑边/花屏类 BUG 另案），但不是本次卡顿主因。

6.2 同显对照

| 模式 | 结果 |

|---|---|

| 同显 WB | 流畅（fence 与视频都在 screen0） |

| 异显 TEMP（fence 仍写死 0） | 卡顿 |

| 异显 + fence 跟 screen1 | 流畅（2026-08-06） |

6.3 次要噪声（非整段卡顿主因）

  • dma_buf fd=0：建层/切歌瞬间（LayerCreate 无 buffer 就 setEnable）
  • 开局 KTV 建层再被 BT/av_player_service 接管

6.4 闭环结论

根因：异显把视频挪到 screen1 后，HWC fence timeline/sync point 仍挂 screen0。

修复：tlayer_ctrl.c 的 fence API 使用 fenceScreenId（异显=1）。

不做：正式 SAME/DIFF 状态机、用户态开关 WB ioctl — 另做。
