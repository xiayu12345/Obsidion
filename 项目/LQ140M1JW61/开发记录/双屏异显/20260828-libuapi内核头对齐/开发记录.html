异显合并后 libuapi 与内核头对齐 — 开发记录

| 项 | 内容 |

|---|---|

| 日期 | 2026-08-28 |

| 范围 | 架构级（glibc-830 工具链头全板共用，不是 ZS 独有） |

| 验证板 | p1_nor_ZS101 |

| 状态 | 已定稿（按官方 include；换工具链头） |

| 前置 | 20260806-同异显切换 |

---

1. 现象

异显 ioctl / disp_fb_info2 合进内核后，media_sessiond 调 DISP_LAYER_SET_CONFIG2：

[DISP] dual display already enabled
[DISP] disp_get_layer (0,0,<很大的数>) fail

脏 layer_id（如 7715360）当下标 → disp_mgr_set_layer_config2 Oops。数字每次开机都变，是栈垃圾。GET_CONFIG2 多半只警告；崩在 SET。

dual display already enabled 只说明 WB 已起来（boot_sync 幂等），不是崩因。

---

2. 根因

内核 kernel/linux-5.4/include/video/sunxi_display2.h 相对工具链旧头变长：

  • disp_fb_info2 中间插入 tfbd_en / tfbc_info
  • 增加 DISP_DUAL_DISPLAY_*（0x407 起）

官方 libuapi：

#include <video/sunxi_display2.h>

Makefile 只有 -I$(LINUX_DIR)/user_headers/include/video。

官方 headers_install 不导出 sunxi_display2.h。<video/sunxi_display2.h> 实际吃：

prebuilt/rootfsbuilt/arm/toolchain-sunxi-glibc-gcc-830/toolchain/include/video/sunxi_display2.h

所以：只重编内核，用户态结构体不会自动跟上。

官方对照（不要混）：

| 包 | 写法 | 实际吃哪份 |

|---|---|---|

| libuapi | #include <video/sunxi_display2.h> | 工具链 |

| tinycedar | #include "sunxi_display2.h" + -I .../include/video | 内核源码 |

---

3. 约束（已确认）

  • 不要改内核头结构去迁就旧用户态
  • 不要给 libuapi 做 kern_inc 手拷
  • 不要 -I 整棵 kernel/.../include（抢 <linux/fb.h>，编挂）
  • 不要改 headers_install / mkkernel.sh 拷进 user_headers
  • 不要把 libuapi 改成 tinycedar 那套引号 + -I include/video

---

4. 定稿做法

  1. libuapi 源码 / Makefile 保持官方（disp_framework.h 用尖括号；Makefile 不加 LICHEE_KERN_DIR/include/video）。
  2. 工具链头换成内核同一份：

源：kernel/linux-5.4/include/video/sunxi_display2.h

目标：

  • prebuilt/rootfsbuilt/arm/toolchain-sunxi-glibc-gcc-830/toolchain/include/video/sunxi_display2.h
  • prebuilt/rootfsbuilt/arm/toolchain-sunxi-musl-gcc-830/toolchain/include/video/sunxi_display2.h（预防切 musl）

旧头可留 *.bak.pre-kernel-align。

  1. 清包再编用户态再 pack（ZS 不要 m，会编 SPL）：
rm -rf out/h133/p1_nor_ZS101/openwrt/build_dir/target/libuapi
./build.sh openwrt_rootfs
./build.sh pack

编译行应只有 -I .../user_headers/include/video，不应出现 kernel/linux-5.4/include/video。

以后改内核这份头：同步覆盖工具链头，并重编 libuapi。

禁止在 WSL/x86 对 libuapi 源码树本地 make / gcc -c（会留下 x86 .o）。

---

5. 试过、不要再用

| 做法 | 为什么不行 |

|---|---|

| 只重编内核 | 用户态仍是短结构 |

| -I 整棵内核 include | 抢 linux/fb.h |

| kern_inc 手拷 | libuapi 特例 |

| 拷进 user_headers | 官方不导出；且 -I .../include/video 对不上 <video/xxx.h> |

| libuapi 改成 tinycedar 写法 | 不是官方 libuapi |

| 削内核 disp_fb_info2 | 禁止 |

---

6. 用户态接口（不必走命令）

disp_mode 只是 CLI。链 -luapi，#include <disp_dual.h>：

sunxi_disp_mode_get(&mode);
sunxi_disp_mode_set(SUNXI_DISP_MODE_DIFF);  /* 异显，写 /etc/disp_mirror_mode */
sunxi_disp_mode_set(SUNXI_DISP_MODE_SAME);
sunxi_disp_hdmi_connected();
sunxi_disp_video_screen_mask();             /* 1=LCD，2=HDMI */

底层 sunxi_dual_display_set_hdmi_output() 只切 HDMI 上 WB 层，产品路径走 sunxi_disp_mode_set。播中切返回 -EBUSY；切完要再起播才按新屏建层。桌面/设置页目前未接。

---

7. 机上怎么测

插 HDMI，停播后再切。不要在蓝牙 K 歌里测（电视不再镜像 UI 是异显设计）。

disp_mode get     # hdmi=1 wb=1；same 时 hdmi_out=1 video_screen=1；diff 时 hdmi_out=0 video_screen=2
disp_mode same    # HDMI=LCD 的 WB；视频 LCD
disp_mode diff    # 关 HDMI WB；视频到 HDMI

再进点歌播一首。偏好 /etc/disp_mirror_mode。没插 HDMI 时 video_screen 一直是 1。

---

8. 串口常一起出现、但不是这次根因

  • cedarc 扫 libaw_mp3dec.so 等：音频库当视频插件，可忽略。
  • dma_buf_get failed, fd=0：TRANS_DISPBUF_FD 下 fb.fd=0（起层还没 ion fd）。内核只对 fd<0 跳过 map。画面可能黑，进程不会因此退出。
  • 蓝牙 K 歌退回桌面：mcu select android ok，与 DMA / 头文件无关。
