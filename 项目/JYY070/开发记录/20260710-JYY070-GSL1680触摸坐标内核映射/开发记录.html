JYY070 GSL1680 触摸坐标内核映射 — 板级验证

| 项 | 内容 |

|---|---|

| 日期 | 2026-07-10 |

| 板型 | p1_nor_JYY070 |

| 关联板型 | p1_nor（GT911，不受影响） |

| 需求 | GSL1680 物理 1024×600 上报与 UI/fb0 1280×800 1:1 对齐 |

| 架构与补丁 | GSL触摸坐标映射（2026-08-25 拆出） |

| 历史合并补丁 | jyy070-gsl1680-tp-report-map.patch（含已删除的 product DTS hunk，新树请用架构目录分片） |

---

1. 背景

| 层 | 分辨率 | 说明 |

|---|---|---|

| GSL1680 固件/芯片 | 1024×600 | ctp_screen_max_x/y，revert_x/y=1 |

| fb0 / LVGL UI | 1280×800 | board.dts 中 fb0_width/height |

| 改前 userspace | 1024×600 | evdev 1:1 上报，点 UI 按钮偏移 |

GSL1680 驱动 bring-up 已完成（I2C、固件、四角 TP 坐标正常）。本记录仅解决 逻辑坐标与 UI 不一致，不重复驱动接入。

1.1 放弃的方案

| 方案 | 不采用原因 |

|---|---|

| board_ui.h + gen_board_ui_from_dts.sh | DTS 重复解析、编包脚本隐式依赖、改共享 evdev.c |

| EVDEV_CALIBRATE 写死 MIN/MAX | 按板编 liblvgl；getevent 仍为 1024×600 |

| 固件直接 patch 到 1280×800 | 维护成本高，Y 轴边界曾出过问题 |

---

2. 方案

在 gslx680new/gslX680.c 的 report_data() 内，于 exchange / revert / TP 边界检查 之后，按 DTS 可选属性做线性缩放；input_set_abs_params 同步为 report 范围。

2.1 DTS 新增属性（可选）

| 属性 | JYY070 取值 | 说明 |

|---|---|---|

| ctp_screen_max_x/y | 1024 / 600 | 已有；芯片物理范围，revert 仍用它 |

| ctp_report_max_x/y | 1280 / 800 | 新增；上报 userspace 的目标范围 |

| 未配置或为 0 | 等于 ctp_screen_max_* | 与改前行为一致，其它板零影响 |

2.2 坐标链路

芯片 raw (1024×600)
  → exchange / revert（按 ctp_screen_max）
  → 边界检查（仍用 screen_max）
  → tp_map_to_report（screen_max → report_max）
  → input_report_abs → getevent / evdev / desk

2.3 p1_nor 隔离

  • CONFIG_TOUCHSCREEN_GSLX680NEW 仅 JYY070 开启；p1_nor 走 GT911，不编 gslX680.c
  • 未配 ctp_report_max_* 的板型驱动行为不变

---

3. 变更文件

| 文件 | 说明 |

|---|---|

| kernel/.../gslx680new/gslX680.c | 读 DTS、report_data 缩放、input_set_abs_params |

| device/.../p1_nor_JYY070/.../board.dts | chips + product 各加 ctp_report_max_x/y |

未改动： LVGL、evdev.c、liblvgl Makefile、GSL 固件 bin。

6. 补丁应用

前置： 板级已切 GSL1680（ctp@40、ctp_name=gsl1680_fornew、ctp_screen_max 1024×600）。若仍为 GT911 节点，须先完成 GSL1680 bring-up 再打补丁。

干净树请用架构目录（驱动 + 本板 DTS 已拆分）：

bash H133-AI-Skills/开发记录/GSL触摸坐标映射/20260710-GSL-ctp_report_max内核映射/patches/apply-gsl-tp-report-map.sh

历史一包补丁（含 device/product/... hunk，新树可能无该路径）：

cd /path/to/H133-AIKTV
patch -p1 < H133-AI-Skills/开发记录/板件开发记录/JYY070/20260710-JYY070-GSL1680触摸坐标内核映射/jyy070-gsl1680-tp-report-map.patch

撤销历史包：

patch -R -p1 < H133-AI-Skills/开发记录/板件开发记录/JYY070/20260710-JYY070-GSL1680触摸坐标内核映射/jyy070-gsl1680-tp-report-map.patch

---

7. 后续同 TP 新板

  1. 保持 ctp_screen_max_* 为芯片物理分辨率（1024×600）
  2. ctp_report_max_* 设为 UI/fb0 逻辑分辨率（如 1280×800）
  3. 无需改 LVGL；p1_nor 等未配属性的板不受影响

---

8. 与 userspace tp_rotate（2026-07-17 定稿）

内核已做 revert_x/y + report_max→1280×800 后，不要再叠 evdev 软旋。

| 配置 | 定稿 | 现象若设错 |

|------|------|------------|

| /etc/setting.ini → tp_rotate | 0 | =2 时左右上下全反（点左上 → UI 右下） |

| disp_rotate | 0（UI 不软旋） | 与触摸无关，但须与 UI 一致 |

优先读 /mnt/UDISK/setting.ini，刷 rootfs 改 /etc 不一定生效。板级总览见 board-profile-p1_nor_JYY070.md。
