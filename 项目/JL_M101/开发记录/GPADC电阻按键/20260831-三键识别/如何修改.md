# 如何改 GPADC 电阻按键配置

只改 **本板 `board.dts` 的 `&gpadc`**，不要改 `sunxi_gpadc.c`。新电压、新键码、增减键都在这张表里完成。

对照：[开发记录.md](./开发记录.md)（读电压第 4 节，测键码第 5 节）

其它仍用全志默认表的板件，可合补丁（电阻网络须相同）：[gpadc-5btn-0R-3.3k-5.1k-6.8k-15k.patch](./gpadc-5btn-0R-3.3k-5.1k-6.8k-15k.patch)

```bash
cd device/config/chips/h133/configs/<BOARD>
patch -p1 < H133-AI-Skills/开发记录/GPADC电阻按键/20260831-三键识别/gpadc-5btn-0R-3.3k-5.1k-6.8k-15k.patch
```

`p1_nor_JL_M101` 当前 DTS 是板乙电压。补丁也是板乙。板甲用 3/106/161/208/404，见 [开发记录.md](./开发记录.md)，不要拿板乙补丁打到板甲上。电压不同的板先 `cat /sys/class/gpadc/data` 实测。

## 0. 改哪个文件

**文件：** `device/config/chips/h133/configs/<BOARD>/linux-5.4/board.dts`

京龙当前是 `p1_nor_JL_M101`。`device/product/configs/<BOARD>/.../board.dts` 若指向同一文件，改一处即可。

搜 `&gpadc {`。不要改全志默认的其它板件 dts，除非那块板 KEY 电压也变了。

改完只编 **kernel**（dtb 打进 boot.img），不必重编 rootfs：

```bash
./tools/build_p1_nor_JL_M101.sh kernel
./build.sh pack
```

禁止在 WSL 本地 `make` 出 `.o`。

## 1. 节点里每项是什么

京龙当前表（复制改）：

```dts
&gpadc {
	channel_num = <1>;
	channel_select = <1>;           /* bit0 = GPADC0，不要改通道除非硬件改了脚 */
	channel_data_select = <1>;
	channel_compare_select = <1>;
	channel_cld_select = <1>;       /* 开低压中断：按下 */
	channel_chd_select = <1>;       /* 开高压中断：松开 */
	channel0_compare_lowdata = <1700000>; /* µV，低于此 = 按下 */
	channel0_compare_higdata = <1550000>; /* µV，高于此 = 松开 */
	key_cnt = <4>;                  /* 下面 key0..key3 的个数，最多 13 */
	key0_vol = <0>;                 /* mV，须从小到大 */
	key0_val = <164>;               /* linux 键码 KEY_PLAYPAUSE */
	key1_vol = <653>;
	key1_val = <165>;               /* KEY_PREVIOUSSONG */
	key2_vol = <1160>;
	key2_val = <163>;               /* KEY_NEXTSONG */
	key3_vol = <1460>;
	key3_val = <240>;               /* KEY_UNKNOWN 占位 */
	status = "okay";
};
```

| 项 | 单位 | 作用 |
|----|------|------|
| `keyN_vol` | **mV** | 这颗键按下时 GPADC0 上的电压（万用表量 KEY 对 GND） |
| `keyN_val` | 键码 | 上报给 `/dev/input` 的 linux code |
| `key_cnt` | 个数 | 必须等于写了的 `key0`…`key{n-1}` 对数 |
| `channel0_compare_lowdata` | **µV** | 低于此才走「按下」；空闲约 1.8V 时用 `1700000` |
| `channel0_compare_higdata` | **µV** | 高于此才走「松开」；必须 **大于最高有效键电压、小于空闲** |

`keyN_vol` 是毫伏，`compare_*data` 是微伏，不要混。`1.16V` → vol 写 `1160`，higdata 写 `1550000`。

## 2. 驱动怎么用这张表（改之前先算窗口）

`key_vol[]` 必须 **严格递增**，且都 **&lt; 1800**。驱动会再塞一个哨兵 `1800`：

```text
窗口 i 的上沿 = key_vol[i] 与 key_vol[i+1] 的中点
```

京龙当前：

```text
电压:     0     653     1160     1460     1800
中点:        326      906      1310      1630

  0～326   → key0 播放/暂停
326～906   → key1 上一曲
906～1310  → key2 下一曲
1310～1630 → key3 占位（1.46V）
>1630      → 当没按（空闲）
```

另外还有硬门槛：采样电压 **≥ 1700mV** 直接当没按。所以：

- 有效键电压必须 **明显低于 1.7V**（建议 ≤ 1.60V）
- 两颗键电压差建议 **≥ 150mV**，否则窗口太窄会抖

加键、改电压后，把中点手算一遍，确认不会和隔壁键、空闲重叠。

## 3. 常见改法

### 3.1 只改某颗键的功能（电压不变）

改对应 `keyN_val`。常用键码（`linux/input-event-codes.h`）：

| 功能 | `keyN_val` | 宏 |
|------|------------|-----|
| 播放/暂停 | 164 | `KEY_PLAYPAUSE` |
| 上一曲 | 165 | `KEY_PREVIOUSSONG` |
| 下一曲 | 163 | `KEY_NEXTSONG` |
| 音量减 | 114 | `KEY_VOLUMEDOWN` |
| 音量加 | 115 | `KEY_VOLUMEUP` |
| 确认 | 28 | `KEY_ENTER` |
| 菜单 | 139 | `KEY_MENU` |
| 忽略/占位 | 240 | `KEY_UNKNOWN` |

dts 里写数字，不要写宏名。

### 3.2 实测电压和表不一致

1. 按下时量 **GPADC0 管脚对 GND**（不是面板 3.3V 侧）
2. 把 mV 写入对应 `keyN_vol`，保持从小到大
3. 重算中点；必要时插一档 `KEY_UNKNOWN` 把窗口隔开
4. 检查 `higdata` 仍高于最高有效键

例：上一曲实测 0.70V → `key1_vol = <700>;`

### 3.3 增加一颗有效键

1. 新电压必须 &lt; 1.7V，并和已有档拉开
2. `key_cnt` +1
3. 按电压插入 `keyN_vol` / `keyN_val`（编号按电压从低到高，不要乱序）
4. 若新键比原来最高有效键还高：把 `higdata` 抬到「新键电压 与 空闲 1.8V」之间

例：要正式接音量减 1.46V，把现在的占位改成：

```dts
key_cnt = <4>;
key3_vol = <1460>;
key3_val = <114>;   /* KEY_VOLUMEDOWN */
/* higdata 仍须 > 1460mV，例如 1550000 已满足 */
```

音量加 1.95V：**不能**写成 `1950`。须先在 GPADC0 上量到稳定 **&lt; 1.65V** 再进表，否则和空闲一样是 ~1.8V。

### 3.4 减少键

`key_cnt` 改成实际对数，删掉后面的 `keyN_*`。若删的是中间档，后面的编号要前移，电压仍从小到大。

删了最高档之后，检查下一档窗口会不会吞掉板上还在的物理键（京龙 1.46V 就是因此留了占位）。

### 3.5 改按下/松开阈值

空闲仍是 1.8V 时：

- `lowdata` 保持 `1700000`（1.7V）一般不用动
- `higdata`：大于「最高有效键 + 余量」，小于 1.7V

| 最高有效键 | higdata 建议 |
|------------|----------------|
| ≤ 0.88V（全志默认） | `1200000` 可用 |
| 1.16V（下一曲） | `1400000`～`1550000` |
| 1.46V（音量减） | `1550000`～`1600000` |

`higdata` 低于某颗键的电压 → 这颗键会按下立刻松开。

## 4. 编译与确认 dtb

```bash
./tools/build_p1_nor_JL_M101.sh kernel
./build.sh pack
```

镜像：`out/h133_linux_p1_nor_JL_M101_uart0_nor.img`

反编译核对：

```bash
dtc -I dtb -O dts out/h133/kernel/build/arch/arm/boot/dts/board.dtb \
  | awk '/gpadc@/,/^[[:space:]]*\};/'
```

十进制对照：`key0_val = <0xa4>` → 164；`key1_vol = <0x28d>` → 653。

## 5. 板上怎么验

见 [开发记录.md](./开发记录.md) 第 4 节读电压、第 5 节 hexdump。改 `keyN_val` 后 hex 里的 code 会变，例如改成 114 则按下是 `72 00` 不是 `a4 00`。

```bash
grep -A 8 'sunxi-gpadc0' /proc/bus/input/devices
hexdump -C /dev/input/eventN
```

## 6. 排错

| 现象 | 先查 |
|------|------|
| 完全没 `sunxi-gpadc0` | `&gpadc` 的 `status`；`channel_select` |
| 短地对地不是 164 | `key0_vol/val` 是否被覆盖；dtb 是否打进这张镜像 |
| 按下立刻松开 | `higdata` 是否低于该键电压 |
| A 键出成 B 键 | `key_vol` 没按从小到大排；中点窗口重叠；少了占位档 |
| 最高那颗永远没事件 | 电压 ≥ 1.7V，或被钳成 1.8V（1.95V 就是这个） |
| 长按刷很多包 | 正常，`value=2` 是 `EV_REP`，不是配错 |

LVGL 此时仍不读 gpadc，**界面不动不算配置失败**。
