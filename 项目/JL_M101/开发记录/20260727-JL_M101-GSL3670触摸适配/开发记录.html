JL-M101 GSL3670 触摸适配 — 开发记录

| 项 | 内容 |

|---|---|

| 日期 | 2026-07-27（报点）→ 2026-07-28（固件/四角）→ 2026-08-03（report 对齐 LVGL） |

| 板型 | p1_nor_JL_M101 |

| 显示定稿 | 20260722-…定稿 |

| 结论 | 触摸可用：event3 报点；固件 startup 0xb0=5a5a5a5a；上报量程 1280×800（对齐 disp_rotate=3 的 LVGL）；tp_rotate=0 |

---

1. 结论（一句话）

板载 GSL3670 用技术支持定稿 GSL3670_JL_M101.h 打成 gsl3670.bin 内嵌内核后可报点且 0xb0 通过；芯片原生轴与屏对调，ctp_exchange_x_y_flag=1，screen_max=report_max=1280×800（交换后保持横屏量程，直接对齐 LVGL，不映回 fb 800×1280）。

源 .h 放在 kernel/.../gslx680new/（与其它板型固件头同目录），不放硬件资料。

---

2. 硬件与管脚

| 项 | 值 |

|---|---|

| 芯片 | GSL3670 |

| 总线 | TWI1（PG8/PG9），地址 0x40 |

| INT | PG3 |

| RST | PG2 |

| 屏 / UI | fb 800×1280 竖屏 → LVGL 1280×800（sunxifb_rot=3 / disp_rotate=3） |

显示定稿阶段 DTS 仍是克隆自 8733 的 gt911@0x5d，与本板不符，须改为 gslX680@0x40。

---

3. 固件来源与打包

3.1 原厂文件角色

| 文件 | 角色 | 能否单独灌芯片 |

|---|---|---|

| conf_3670(3).set | 项目配置 + 残缺 FW（~264 条） | 否 |

| GSL3670_JL_M101.h（技术支持定稿） | 完整 FW+config（0x3200500 / 800×1280） | 是（经打包） |

| 工具包 set/GSL3670.h / default_3670.h | 出厂默认 480×800（0x1e00320） | 是，但量程不对 |

| main_3670.set / .dump | 工具写入流 / 符号表 | 不直接给 Linux |

早期不完整包 startup 后 0xb0=eed48611（驱动判 FAIL）仍可报点；定稿 .h 后两次 startup 均为 5a5a5a5a，无二次失败重 init。勿把旧魔数 FAIL 当成「芯片坏」。

3.2 定稿路径与 bin

| 角色 | 路径 |

|---|---|

| 源 .h | kernel/linux-5.4/drivers/input/touchscreen/gslx680new/GSL3670_JL_M101.h |

| 打包工具 | tools/gsl_pack_firmware.py |

| 运行 / EXTRA_FIRMWARE | openwrt/target/h133/h133-p1_nor_JL_M101/busybox-init-base-files/lib/firmware/gsl_firmware/gsl3670.bin |

| 补丁副本 | …/patches/files/gsl3670.bin |

tools/gsl_pack_firmware.py \
  kernel/linux-5.4/drivers/input/touchscreen/gslx680new/GSL3670_JL_M101.h \
  --fw-array GSLX680_FW --config-array gsl_config_data_id \
  --name gsl3670 \
  -o openwrt/target/h133/h133-p1_nor_JL_M101/busybox-init-base-files/lib/firmware/gsl_firmware/gsl3670.bin
# 同步一份到 patches/files/gsl3670.bin 供 apply 脚本

| 属性 | 值 |

|---|---|

| md5 | 26c831f3d9884fecc5fdbd329d863a3e |

| 大小 | 42227 |

| config 分辨率字段 | 0x3200500 → 800×1280（芯片侧；userspace 上报见 §4） |

| config id | 0xd93b89 |

| startup 0xb0 | 5a5a5a5a (OK) |

备件（历史 A/B）：旧 800×1280 不完整包 426e9c81…（0xb0=eed48611 仍可报点）；默认 480×800 包 82f220d2…。

3.3 必须内嵌内核

CONFIG_EXTRA_FIRMWARE="gsl_firmware/gsl3670.bin"
CONFIG_EXTRA_FIRMWARE_DIR="../../openwrt/target/h133/h133-p1_nor_JL_M101/busybox-init-base-files/lib/firmware"

probe 优先用 builtin。只换 rootfs 无效。换 bin 后：

rm -rf out/h133/kernel/build/drivers/base/firmware_loader/builtin/gsl_firmware
./tools/build_p1_nor_JL_M101.sh kernel
# 再 p 打包

4. 软件改动清单

| 路径 | 改动 |

|---|---|

| device/.../p1_nor_JL_M101/linux-5.4/board.dts（及同板 board.dts） | ctp@5d gt911 → ctp@40 gsl3670；坐标见下 |

| device/.../p1_nor_JL_M101/linux-5.4/config-5.4 | EXTRA_FIRMWARE 指向 gsl3670.bin |

| openwrt/.../gsl_firmware/gsl3670.bin | 定稿芯片 800×1280 包（md5 26c831f3…） |

| kernel/.../gslx680new/GSL3670_JL_M101.h | 技术支持定稿源头（与其它板型 .h 并列） |

| tools/gsl_pack_firmware.py | .h → Allwinner bin 打包工具 |

| kernel/.../gslx680new/gslX680.c | CTP_IRQ_MODE = IRQF_TRIGGER_FALLING；request_firmware 加载 gsl3670.bin |

4.1 坐标定稿（DTS，2026-08-03）

/* exchange 后 1280×800；report 保持同量程，对齐 LVGL（disp_rotate=3） */
ctp_screen_max_x = <1280>;
ctp_screen_max_y = <800>;
ctp_report_max_x = <1280>;
ctp_report_max_y = <800>;
ctp_revert_x_flag = <0x0>;
ctp_revert_y_flag = <0x0>;
ctp_exchange_x_y_flag = <0x1>;

驱动 report_data() 顺序：先 exchange → 再按 screen_max 裁剪 → 再 tp_map_to_report(screen→report)。

report_max == screen_max 时为恒等映射（无缩放）。

setting.ini 的 tp_rotate=0（方向在 DTS；不要靠改 tp_rotate 凑 UI）。

5. 实机现象与判定

5.1 A/B（固件）

| 固件 | 0xb0 | 触摸 |

|---|---|---|

| 480×800（82f220d2…） | 5a5a5a5a | 有报点，量程约 480×800 |

| 早期 800×1280（426e9c81…） | eed48611 | 有报点；驱动打 mismatch，但不挡 IRQ |

| 定稿 800×1280（26c831f3…） | 5a5a5a5a | 有报点；startup 通过，无二次失败重 init |

说明：eed48611 时 _check_chip_state 判未就绪；本板曾关 monitor 重灌仍可读点。定稿后不再依赖该绕过。试验过 GSL_MONITOR 盯 0xb4，不能把坏包的 0xb0 变成 5a5a5a5a。

5.2 坐标调校过程（2026-07-28，历史）

四角点击顺序：左上 → 右上 → 左下 → 右下。

| 阶段 | DTS | 现象 |

|---|---|---|

| 仅报点 | exchange=0，screen/report=800×1280 | 有点，但 X/Y 对调（左右进 Y，上下进 X） |

| 只开 exchange | exchange=1，screen_max 仍 800×1280 | 左半边正常；右半边只有 BTN、无 ABS（交换后 X≈1266 > SCREEN_MAX_X=800，驱动直接 return） |

| 07-28 阶段 | exchange=1，screen_max=1280×800，report_max=800×1280 | getevent 四角落在约 800×1280，与物理竖屏一致 |

07-28 验收样例（report_max=800×1280 时）：

| 位置 | 上报 (X,Y) |

|---|---|

| 左上 | (11, 35) |

| 右上 | (783, 27) |

| 左下 | (7, 1251) |

| 右下 | (781, 1252) |

5.3 对齐 LVGL（2026-08-03）

| 项 | 内容 |

|---|---|

| 现象 | getevent 四角约 800×1280 正常，但 desk（disp_rotate=3，LVGL 1280×800）点图标无响应 |

| 根因 | report_max 把交换后的 1280×800 又映回 fb 800×1280；EVDEV_CALIBRATE=0 且 tp_rotate=0 时 raw 直接当 LVGL 坐标，对不上 |

| 处理 | ctp_report_max_* 改为 1280×800（与 screen_max 相同）；不改 tp_rotate |

| 改动文件 | device/.../p1_nor_JL_M101/{,linux-5.4/}board.dts |

| 镜像 | out/h133_linux_p1_nor_JL_M101_uart0_nor.img md5 e8bb8718230399d5c2ed958d73f9a29b |

| DTB 核对 | ctp_report_max_x/y = <0x500>/<0x320>（1280/800） |

刷机后期望：getevent 四角落在约 1280×800；desk 点图标命中（仍 tp_rotate=0）。

5.4 验收命令

cat /proc/bus/input/devices   # Name=gslX680 → event3
dmesg | grep -E 'gsl|0xb0|irq-status|ctp-startup|report map'
getevent -p /dev/input/event3
getevent -l /dev/input/event3   # 左上→右上→左下→右下

期望：startup 0xb0=5a5a5a5a；ABS 量程约 1280×800；四角与横屏 UI 一致；无需改 tp_rotate。

5.5 踩坑

  1. .set 不能单独打包：须完整 .h；工具包默认头是 480×800。
  2. builtin 固件缓存：不删 …/builtin/gsl_firmware 会链到旧 bin。
  3. 早期 0xb0≠5a5a ≠ 硬件坏：不完整包仍可报点；定稿后应看到 5a5a5a5a。
  4. 上升沿曾试过：空闲 INT 为低时 irq_cnt=0；本板用 falling。
  5. 显示定稿里的 gt911 节点必须换掉，否则不会绑到 0x40。
  6. 只开 exchange 不够：screen_max 须跟交换后芯片量程（1280×800），否则右侧点被丢掉。
  7. report_max 勿映回 fb：映回 800×1280 只对齐物理 fb，不对齐 disp_rotate=3 后的 LVGL；应保持 1280×800。
  8. .h 放哪：与其它板型一样放 gslx680new/；不要放硬件资料或仅开发记录 patches/files/。
