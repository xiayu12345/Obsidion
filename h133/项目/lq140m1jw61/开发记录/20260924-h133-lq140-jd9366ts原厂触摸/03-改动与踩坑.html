03 — 改动过程与踩坑

1. 为何弃用自写 jd9366ts.c

自写能报点，但 backdoor、报告格式、多指/压力与原厂不一致。要求「按原厂」→ 整包 jdchipset。
该调试驱动已从内核树删除（源码 / Kconfig / Makefile / bsp 项），勿再合入。

2. 编译踩坑

现象处理
jadard_hid.o 无规则zip 无 hid；用 patches/files/Makefile.jdchipset
mpap_pw 无成员开 CONFIG_TOUCHSCREEN_JADARD_SORTING
__bad_copy_todebug copy_from_user 限长 + Makefile -D_FORTIFY_SOURCE=0
m kernel 后 openwrt 报 fail若已 compile Kernel successful，直接 p
WSL 卡死重启 Ubuntu 后再编

3. IC ID

原厂期望 0x9386。本 CSOT 模组曾见 0x9032。
GetID / chip_detect 兼收二者（03-jdchipset-ic-id.patch）。

4. 坐标：交换 + Y 镜像（定稿）

4.1 原厂交换 XY

移植指南：由驱动交换时改 Resolution：

jadard_report_points：JD_X_RES > JD_Y_RES 时上报 ABS_X=芯片Y，ABS_Y=芯片X。

实机交换后四角（点击顺序 左上→右上→左下→右下）曾为：

角XY
左上~46~1128
右上~1875~1126
左下~18~91
右下~1876~59

→ X 已对，Y 上下反。

4.2 本板 Y 镜像

在交换分支对 Y：JD_Y_RES - 1 - 芯片X（04-jdchipset-y-mirror.patch）。
期望左上 (小,小)、右上 (大,小)、左下 (小,大)、右下 (大,大)。

tp_rotate 保持 0（无单独翻 Y 的档位；且 getevent 需与桌面一致，故放驱动）。

5. 勿再合入

  • jd9366ts.c / TOUCHSCREEN_JD9366TS / compatible=jadard,jd9366ts / ctp@68 的 ctp_* 节点
  • show_ui_img 顶替 desk（已删）
  • 自写 remap / 靠改 tp_rotate 碰运气而不改 panel-coords + Y 镜像

清理核对（定稿树应全无）：

6. 固件

模组 FW 出厂已烧；不开 JD_AUTO_UPGRADE_FW。升级按移植指南单独做。
