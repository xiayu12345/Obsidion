JYY070 GSL1680 触摸坐标内核映射 — 板级验证

项内容
日期2026-07-10
板型p1_nor_JYY070
关联板型p1_nor（GT911，不受影响）
需求GSL1680 物理 1024×600 上报与 UI/fb0 1280×800 1:1 对齐
架构与补丁GSL触摸坐标映射（2026-08-25 拆出）
历史合并补丁jyy070-gsl1680-tp-report-map.patch（含已删除的 product DTS hunk，新树请用架构目录分片）

1. 背景

层分辨率说明
GSL1680 固件/芯片1024×600ctp_screen_max_x/y，revert_x/y=1
fb0 / LVGL UI1280×800board.dts 中 fb0_width/height
改前 userspace1024×600evdev 1:1 上报，点 UI 按钮偏移

GSL1680 驱动 bring-up 已完成（I2C、固件、四角 TP 坐标正常）。本记录仅解决 逻辑坐标与 UI 不一致，不重复驱动接入。

1.1 放弃的方案

方案不采用原因
board_ui.h + gen_board_ui_from_dts.shDTS 重复解析、编包脚本隐式依赖、改共享 evdev.c
EVDEV_CALIBRATE 写死 MIN/MAX按板编 liblvgl；getevent 仍为 1024×600
固件直接 patch 到 1280×800维护成本高，Y 轴边界曾出过问题

2. 方案

在 gslx680new/gslX680.c 的 report_data() 内，于 exchange / revert / TP 边界检查 之后，按 DTS 可选属性做线性缩放；input_set_abs_params 同步为 report 范围。

2.1 DTS 新增属性（可选）

属性JYY070 取值说明
ctp_screen_max_x/y1024 / 600已有；芯片物理范围，revert 仍用它
ctp_report_max_x/y1280 / 800新增；上报 userspace 的目标范围
未配置或为 0等于 ctp_screen_max_*与改前行为一致，其它板零影响

2.2 坐标链路

芯片 raw (1024×600)
  → exchange / revert（按 ctp_screen_max）
  → 边界检查（仍用 screen_max）
  → tp_map_to_report（screen_max → report_max）
  → input_report_abs → getevent / evdev / desk

2.3 p1_nor 隔离

  • CONFIG_TOUCHSCREEN_GSLX680NEW 仅 JYY070 开启；p1_nor 走 GT911，不编 gslX680.c
  • 未配 ctp_report_max_* 的板型驱动行为不变

3. 变更文件

文件说明
kernel/.../gslx680new/gslX680.c读 DTS、report_data 缩放、input_set_abs_params
device/.../p1_nor_JYY070/.../board.dtschips + product 各加 ctp_report_max_x/y

未改动： LVGL、evdev.c、liblvgl Makefile、GSL 固件 bin。

7. 后续同 TP 新板

  1. 保持 ctp_screen_max_* 为芯片物理分辨率（1024×600）
  2. ctp_report_max_* 设为 UI/fb0 逻辑分辨率（如 1280×800）
  3. 无需改 LVGL；p1_nor 等未配属性的板不受影响

8. 与 userspace tp_rotate（2026-07-17 定稿）

内核已做 revert_x/y + report_max→1280×800 后，不要再叠 evdev 软旋。

配置定稿现象若设错
/etc/setting.ini → tp_rotate0=2 时左右上下全反（点左上 → UI 右下）
disp_rotate0（UI 不软旋）与触摸无关，但须与 UI 一致

优先读 /mnt/UDISK/setting.ini，刷 rootfs 改 /etc 不一定生效。板级总览见 board-profile-p1_nor_JYY070.md。
