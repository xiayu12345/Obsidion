2. 为什么从 MIPI 改成 LVDS

旧 lunch 名 p1_nor_JL_M101 是京龙 MIPI 800×1280 + JD9365DA init 表。K1 接的是厂 LVDS 屏，物理已是 1280×800 横屏。2026-09-11 板件已改名为 p1_nor_XYC_K1（内容仍是 K1，不是京龙原厂）。京龙开屏驱 jl_m101_jd9365da 也改成了 xyc_k1_lvds，后面加回 JL 板件时可以重新放入原厂 MIPI 驱。

若继续走 MIPI 驱：dsi_gen_wr 无 DSI 从机，开屏可能卡住。
若用 default_lcd：同样可能发 MIPI 命令。

做法：Kconfig 用 LCD_SUPPORT_XYC_K1_LVDS，.c 只做电源/PWM helper，时序全部放 dts。

开屏顺序：

内核侧类型是 struct __lcd_panel / struct panel_extend_para。
U-Boot 侧必须是 __lcd_panel_t / panel_extend_para（与 jyy070_lvds.c 一致），否则 NOR U-Boot 编不过，打包会继续用旧的大 u-boot-spinor.fex。

3. 不配 LVDS 极性（2026-09-11）

厂 fex 有 io_polarity=15、clk_polarity=1。09-09 曾写成 dts lcd_lvds_io_polarity=0x1f，并改 lowlevel_v2x/de_lcd.c 的 tcon0_cfg，按该字段写 tcon0_lvds_data_revert / tcon0_lvds_clk_revert。

这套改动没有进 H133 实际在跑的 TCON 路径：

点事实
编译对象CONFIG_ARCH_SUN8IW20 / CONFIG_MACH_SUN8IW20 编的是 de_lcd_sun50iw10.c，不是 de_lcd.c（见 lowlevel_v2x/Makefile）
de_lcd_sun50iw10.c极性写在 #if defined(LVDS_REVERT) 里，且写死 data_revert=0xf、clk_revert=1，不读 dts
LVDS_REVERTsun8iw20 的 de_feat.h 未定义，所以上面整段被编译掉
实测不配 lcd_lvds_io_polarity 也能亮屏、无花屏

定稿：dts 不再写该字段；de_lcd.c 恢复原厂 LVDS_REVERT 写法；不要再给 de_lcd_sun50iw10.c 接 dts 极性。原厂 disp_lcd.c 解析 lcd_lvds_io_polarity 的代码未动（其它平台仍可用）。对应补丁 05-drop-lvds-io-polarity.patch。

4. PhoenixSuit 烧写 boot1 失败

现象：

  • 工具：download_boot1 / 烧写 boot1 (数据流分区) 失败
  • 串口：boot1 size = 0xec000，toc last block : 0x7e0, over write logical ... 0x7a0，stop toc download

原因：NOR 给 boot1 的空间到 logical（2016）之前要扣 U-Boot offset 128 和 secure 64。包超过 933888 就会盖 logical，下载直接停。

sun8iw20p1_nor_defconfig 是精简 defconfig。Kconfig 里 HE0801 / WilliamLcd / LQ101 / inet / CC080 / JYY070 默认 y，make xxx_nor_defconfig 会把它们编进 NOR U-Boot。再加上 LQ140/LQ190/ZS101，包到 966656。

修复：在 nor_defconfig 里对这些符号写 # ... is not set，只留 CONFIG_LCD_SUPPORT_XYC_K1_LVDS=y。

修完后大约：

文件大小
u-boot-spinor.fex491520
boot_package_nor.fex884736（上限 933888，余约 48KB）

注意：

  • LICHEE_BRANDY_DEFCONF 必须是 sun8iw20p1_defconfig。写成 sun8iw20p1_nor_defconfig 会变成 sun8iw20p1_nor_nor_defconfig。
  • NOR 构建会先编 eMMC defconfig 再编 nor；官方脚本会删 .config 强制重配。
  • 不要只改 U-Boot LOGICAL_OFFSET 来腾空间，boot0/spl 也是 CFG_SPINOR_LOGICAL_OFFSET=2016，两边必须一致。

5. UI 旋转

控制不在 dts 里转画面，是 LVGL 读 ini 后 sunxifb_init(rotated)。

优先级：/mnt/UDISK/setting.ini → /etc/setting.ini → LV_ORIENT_DEFAULT_DISP → argv[1]。

本板旧值是 MIPI 竖屏时代的 disp_rotate=1（逻辑画布变成 800×1280）。LVDS 已是 1280×800，再转 90° 画面是竖的。

已改：

键旧新
disp_rotate10
tp_rotate02（LVGL 180°，不改内核）
video_rotate20
video_screen_*800×12801280×800
LV_ORIENT_DEFAULT_DISP/TP3 / 20 / 0

阳光 KTV 窗坐标由旧 90° DE 反算回 1280×800 UI（home 37,128,719,404；lb 37,541,373,210）。

dual_display_rot 已是 0，内核 FB 不再软旋。

原厂 BL3676 没有方向控制（无 ctp_revert_x/y_flag），不要往节点里塞 GSL 属性。画面不软旋（disp_rotate=0），触摸在 LVGL 里 tp_rotate=2（左上↔右下）。

烧完若触摸仍反： PhoenixSuit 通常不覆盖 UDISK。删 /mnt/UDISK/setting.ini 再重启，rc.final 会从 /etc 再拷。
