2.2 软件目标

  1. 内核 probe 成功，/dev/input/event* 有 gt9xxnew_ts；
  2. 分辨率与屏一致：物理竖屏 800×1280（DTS + Config）；应用层可按产品选 1280×800 逻辑横屏（见 §7）；
  3. I2C 地址按规格书 默认 0x14（复位时 INT 为高 → 8 位写 0x28）；
  4. LVGL 通过 evdev ABS 读触摸，可与 USB 鼠标并存。

4. 开发过程（分阶段）

阶段 A：调研与规格对齐

  1. 阅读 GT9110-Datasheet_20121205.pdf：
    • I2C ≤ 400kHz（与 board.dts clock-frequency = <400000> 一致）；
    • 地址 0x28/0x29（7bit 0x14）或 0xBA/0xBB（7bit 0x5d），上电由 RST+INT 时序选定；
    • 配置寄存器 0x8048~0x804B 为 X/Y 最大值。
  2. 确认工程已有 gt9xxnew，T113 等 defconfig 默认 CONFIG_TOUCHSCREEN_GT9XXNEW_TS=y。
  3. 整理对照表 → GT9110-规格书要点与驱动对照.md。

阶段 B：内核与设备树

B.1 bsp_defconfig

文件：device/config/chips/h133/configs/p1_nor/openwrt/bsp_defconfig

操作配置项
关闭 GSL# CONFIG_TOUCHSCREEN_GSLX680NEW is not set
去掉 GSL 固件# CONFIG_EXTRA_FIRMWARE is not set
开启 GT9CONFIG_TOUCHSCREEN_GT9XXNEW_TS=y
保持CONFIG_INPUT_SENSORINIT=y、CONFIG_INPUT_TOUCHSCREEN=y

B.2 board.dts

文件：device/config/chips/h133/configs/p1_nor/linux-5.4/board.dts，节点在 &twi1 下：

注意：勿再 enable &twi2 下旧模板 ctp@14（PB8/PB9），避免与 PG2/PG3 冲突。

B.3 触摸配置组 gt9xx.h

文件：kernel/linux-5.4/drivers/input/touchscreen/gt9xxnew/gt9xx.h

  • 默认 ctp_name = "gt9xxnew_ts" 使用 CTP_CFG_GROUP1；
  • 将 Config 中分辨率改为 800×1280（对应寄存器 0x8048~0x804B，小端）：
    • X：0x20, 0x03 → 0x0320 = 800
    • Y：0x00, 0x05 → 0x0500 = 1280
  • GTP_INT_TRIGGER = 0：上升沿（规格书默认 00）；
  • 校验和由驱动 gtp_send_cfg 前 自动重算，无需手改末尾 checksum。

若屏厂提供专用 .cfg，可新增 ctp_name（如 gt9110_xxx）并在 gt9xx.c 的 config_info.name 分支映射到对应 CTP_CFG_GROUPx（参考已有 gt9110_wt097 / gt9110_g200）。

B.4 编译

烧录：out/h133_linux_p1_nor_uart0_nor.img（以实际产物为准）。

阶段 C：板上内核验证

期望：

  • i2cdetect -y 1 在 0x14 为 UU（若只见 0x5d，改 DTS 为 0x5d 并确认复位时 INT 为低）；
  • dmesg 有 Guitar reset、gt9xxnew_ts 注册成功；
  • getevent 有 BTN_TOUCH / ABS_MT_POSITION_*。

阶段 D：LVGL / evdev 对接

D.1 evdev_touch_init()

文件：platform/thirdparty/gui/lvgl-8/lv_drivers/indev/evdev.c

逻辑：

  1. 若存在 /dev/input/touchscreen 则优先打开；
  2. 否则扫描 event0…event15，检测 ABS_MT 或 ABS_X；
  3. 设备名含 gt9xx 优先绑定。

启动 log 示例：evdev touch opened: /dev/input/event3

D.2 lv_projector

文件：

  • lv_projector/src/main.c：indev_touch_drv + evdev_read（POINTER）；
  • lv_projector/src/lv_drv_conf.h：EVDEV_SWAP_AXES=0，EVDEV_CALIBRATE=0。

可与 USB 鼠标并存，详见 H133-USB鼠标与GT911触摸并存-lvgl.md。

D.3 专用测试程序 lv_tp_test

拓步 10.1 阶段用 lv_tp_test 白底画点验证坐标，流程见 tuopu-10.1-h133-tp-lvgl。

7. 坐标与分辨率说明（易混点）

层级典型取值说明
物理 LCD800×1280 竖屏board.dts ctp_screen_max_x/y
GT911 Config800×1280CTP_CFG_GROUP1 字节
芯片实际上报常见 01279 × 0799横屏逻辑 1280×800，与拓步 UI 一致
LVGL lv_tp_test1280×800 + sunxifb 90°仅 fb 旋转，勿再开 disp_drv.rotated 叠转
GSL 时代DTS 曾写 1280×800 交换已废弃，GT9 勿照搬 GSL 的 swap 写法

若触摸与画面对不齐：

  1. 用 getevent 看 raw 范围；
  2. 调 ctp_exchange_x_y_flag / ctp_revert_x/y_flag；
  3. 或 Config 里 X2Y（0x804D）与 EVDEV_SWAP_AXES（仅应用层）二选一，避免双重交换。

双显 + MIPI 软转见：H133-双显-LVGL软转实践总结.md。

8. 常见问题

现象可能原因处理
i2cdetect 无 0x14/0x5d供电、FPC、TWI 引脚错（非 PG8/9）对原理图；测 3.3V
地址是 0x5d 而非 0x14模组 RST/INT 时序选低地址DTS 改 0x5d
dmesg 无 gt9未编进内核、DTS status 非 okay查 bsp_defconfig、重编 kernel
probe 失败 / Config invalidConfig 组与屏不匹配向屏厂要 .cfg 或换 gt9110_* 组
有驱动无坐标INT 边沿反了改 GTP_INT_TRIGGER 或 0x804D
LVGL 无触摸未走 evdev_read、节点被占用evdev_touch_init log；killall 再测
触摸与画面错位双重旋转或 XY 重复交换见 §7；对照 tuopu 文档
与 GSL 混用仍加载 gsl_firmware确认 GSL Kconfig 与固件已关

9. 从 GSL 迁回 GT9110 的检查表

  • bsp_defconfig：GT9XXNEW_TS=y，GSLX680NEW 关，无 EXTRA_FIRMWARE GSL bin
  • board.dts：allwinner,goodix，0x14，800×1280，PG2/PG3，仅 twi1 下 enable
  • gt9xx.h：Config 分辨率 / 中断沿
  • 重编 kernel + rootfs（lv_projector） 并烧录
  • i2cdetect -y 1、getevent、evdev touch opened
  • UI 点按与显示对齐（必要时调 mirror / X2Y）
