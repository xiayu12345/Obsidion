H133 触摸屏（CTP）驱动开发

本文基于本工程（H133-02，芯片 sun8iw20 / H133，板级 p1_nor）源码与 TP-H10 主板 bring-up 记录整理，说明 电容触摸（CTP） 在全志 Tina Linux 上的设备树、内核驱动、固件与应用对接方式。

  • H133-LCD背光亮度-硬件供电分析.md — 主板供电与原理图

1. 硬件与接口（TP-H10）

1.1 本板 CTP 走线（与备份一致）

原理图 CTP 接 SoC TWI1（注释见 board.dts：PG8 = CTP-SCK，PG9 = CTP-SDA）。不要与 twi2（PC0/PC1）或旧 demo 的 PB8/PB9 混淆。

信号备份 DTS（已调通）说明
I2C 总线twi1，ctp_twi_id = <1>用户空间 i2cdetect -y 1
I2C 地址0x40GSL 系列常见地址
中断 INTPG3ctp_int_port
复位/唤醒 RSTPG2ctp_wakeup
触摸 ICSilead GSL（驱动名 gslX680）非 GT9

1.2 与显示的关系

触摸与 LCD 独立：显示走 disp / default_lcd / MIPI DSI；触摸走 I2C + input 子系统。出现「有背光无图」或「有图无触摸」时，应 分开排查（参见 H133-MIPI-HDMI双显开发记录.md §4.6）。

1.3 触摸有效区域

10.1 寸 MIPI 主屏为 800×1280 时，DTS 中应使用：

  • ctp_screen_max_x = <0x320>（800）
  • ctp_screen_max_y = <0x500>（1280）

旧模板里的 0x1e0（480）对应其它分辨率屏，不能直接用于本板竖屏。

4.3 禁用错误总线上的旧节点

当前工程在 &twi2 下仍保留 GT9（0x14，PB8/PB9）与 Focaltech 模板，且均为 disabled。对齐 TP-H10 后应：

  • &twi2：status = "disabled"，并注释说明 CTP 不在此总线；
  • 勿 enable 与 PG2/PG3 冲突的 GPIO 定义。

4.4 DTS 属性说明（init-input.c 解析）

属性含义
status必须为 okay，否则 ctp_used = 0，驱动直接退出
ctp_twi_idTWI 控制器编号（twi1 → 1）
ctp_twi_addr7 位 I2C 地址
ctp_nameGSL 固件文件名（不含路径/后缀）：gsl_firmware/<ctp_name>.bin
ctp_int_port中断 GPIO
ctp_wakeup复位/唤醒 GPIO
ctp_screen_max_x/y逻辑坐标上限，与屏分辨率一致
ctp_revert_x/y_flagX/Y 镜像
ctp_exchange_x_y_flagX/Y 对调
ctp-supply / ctp_power_ldo可选，触摸独立 LDO 时配置

5.2 GSL 固件

驱动加载逻辑（gslx680new/gslX680.c）：

要求：

  1. 文件名为 mtk_gslX680.bin（与 ctp_name 一致）；
  2. 放置路径（二选一或同时）：
    • 编进内核：CONFIG_EXTRA_FIRMWARE + CONFIG_EXTRA_FIRMWARE_DIR（备份指向 openwrt/target/h133/h133-p1_nor/busybox-init-base-files/lib/firmware）；
    • 或 rootfs：/lib/firmware/gsl_firmware/mtk_gslX680.bin。
  3. 固件须由 屏厂/模组厂 提供，与玻璃、IC 型号、校准一致；不能用别家平台的表代替。

若仓库中暂无 .bin，可从 备份工程编译产物 或模组资料包中提取，再放入上述目录。

5.3 GT9 / Focaltech 简要说明

  • GT9：compatible = "allwinner,goodix"，ctp_name = "gt9xxnew_ts"，驱动 gt9xxnew/gt9xx.c，同样依赖 init-input，late_initcall 注册。
  • Focaltech：更偏标准 focaltech,fts 节点（focaltech,reset-gpio / focaltech,irq-gpio），与全志 ctp_* 命名并存时需只 enable 一套。

6. 开发流程（bring-up 清单）

6.1 硬件确认

  1. 读原理图：TWI 号、SCL/SDA、INT、RST、供电。
  2. 上电后 i2cdetect -y <bus>，确认从机地址（本板期望 0x40）。
  3. 确认与 耳机检测 等复用：注释要求 PG8 勿作 hp-det。

6.2 修改设备树

  1. 修正 twi1_pins → PG8/PG9。
  2. 在 &twi1 下添加/恢复 ctp@40，status = "okay"。
  3. 分辨率、翻转标志与 MIPI 方向一致。
  4. 关闭 twi2 上错误 ctp 节点。

6.3 修改内核配置并编译

改过 DTS 或内核 必须走 full；仅改 rootfs 且不动 boot 时可用 rootfs 目标。

6.4 板上验证

期望：

  • 出现 gslX680 设备名；
  • 触摸时有 ABS_MT_POSITION_X/Y 或 ABS_X/Y 事件；
  • 坐标范围约 0～799 / 0～1279（竖屏）。

6.5 坐标与应用

  • 坐标颠倒/镜像：只调 DTS 三个 flag 和 ctp_screen_max_*，优先不要改应用。
  • 芯片量程 ≠ UI：ctp_report_max_* 内核线性缩放，见 GSL触摸坐标映射。
  • lv_projector：evdev.c 按名称自动查找 gslX680 的 event 节点。
  • lv_ds：配置项 touch_dev（如 /dev/input/event0），见 LV_DS-双屏异显中间件架构.md。
