## 1. 结论（先看这个）

| 决策 | 取值 / 做法 |
|---|---|
| lunch | `h133-p1_emmc_JL_M101-tina` |
| autoconfig | `./build.sh autoconfig -o openwrt -i h133 -b p1_emmc_JL_M101 -n default`（不是 `-n nor`） |
| 屏 | 仍是京龙 MIPI **800×1280**，`lcd_driver_name = "jl_m101_jd9365da"` |
| 触摸 | 仍 GSL3670，`setting.ini` 仍 `disp_rotate=1` |
| 存储 | `storage_type = 2`（eMMC / card2） |
| eMMC 电气 | **3.3V 4bit**，不开 1.8V HS200/HS400；PC2–PC7 给 SDC2 |
| SPI0 / NOR | **禁用**（与 eMMC 复用 PC） |
| 分区 | 抄 LQ140 eMMC：`boot`/`rootfs` 加大，`env-redund`，`UDISK` 吃剩余 |
| root | `bootcmd=run setargs_mmc boot_normal`，`mmc_root=/dev/mmcblk0p5` |
| 开机 logo | 必须用板级 **100×432** 竖图；common 默认是 **312×76 横图** |

K1 没有 16G eMMC 工程。同 SDK 里现成的 16G eMMC 只有音乐骑士 `p1_emmc_LQ140M1JW61`，所以存储按它抄，屏和 UI 按 NOR 京龙抄。

---

## 2. 为什么要整板复制

用户要求：完整复制京龙板件，改成 eMMC；屏驱继续用 JL 的，只把 flash 改成 eMMC。

不能在 `p1_nor_JL_M101` 上改 `storage_type`：NOR 工程还要留着。新建 `p1_emmc_JL_M101`，device + OpenWrt target 整树复制后再改存储相关文件。

eMMC 与 SPI NOR 共用 **PC2–PC7**。开 eMMC 必须关 SPI0，否则脚复用冲突。

---

## 3. 存储怎么改（相对 NOR 京龙）

模板是 LQ140 NOR→eMMC 那套，不是自己发明分区。

| 文件 | 改动 |
|---|---|
| `sys_config.fex` | `storage_type = 2` |
| 分区 | 删 `sys_partition_nor.fex`，用 LQ140 eMMC 的 `sys_partition.fex` |
| 内核 `&sdc2` | `okay`，`bus-width=4`，3.3V，去掉 1.8V HS200 |
| 内核 `&spi0` | `disabled` |
| U-Boot | `spi0 disabled`，`pc_bias = 3300`，去掉 `sdc_io_1v8` |
| `env.cfg` | `bootcmd=run setargs_mmc boot_normal`，`mmc_root=/dev/mmcblk0p5` |
| `openwrt/BoardConfig.mk` | `LICHEE_REDUNDANT_ENV_SIZE:=0x20000` |
| `BoardRules.mk` | 沿用 LQ140 eMMC 分区镜像尺寸 |

分区表（扇区单位在 pack 日志里展开；`UDISK` 无 `size`，吃 16G 剩余）：

```text
boot-resource  1024
env            512
env-redund     512
boot           30720
rootfs         256000
rootfs_data    32768
UDISK          （剩余）
```

下载镜像本身只有约 **25MB**（boot-resource + env + boot + squashfs rootfs）。GPT 里 UDISK 到盘尾，上电后展开，所以 img 不是 16GB。

U-Boot 非 NOR defconfig `brandy/brandy-2.0/u-boot-2018/configs/sun8iw20p1_defconfig` 已加 `CONFIG_LCD_SUPPORT_JL_M101_JD9365DA=y`（与 LQ140 等屏驱共存）。eMMC 走这套 U-Boot，不走 `sun8iw20p1_spinor_defconfig`。

## 4. 开机 logo 为什么一度是横的

U-Boot `boot_package.cfg` 里 `item=logo` 是注释掉的，开机图来自 **boot-resource 分区**里的 `bootlogo.bmp`。

`build/pack` 在 OpenWrt 打包时会先把 `h133-common/boot-resource` 整目录拷进 `pack_out`，把板级 bmp 盖掉。common 那张是 **312×76 横图**。

原先只有硬编码：

```text
PACK_BOARD == p1_nor_JL_M101
```

才把板级 **100×432** 竖图拷回去。`p1_emmc_JL_M101` 第一次出的镜像（MD5 `d2a4f5510a069139fe6629f543ee1ae6`）boot-resource 里就是横图。

已改成 NOR / eMMC 两块京龙板都覆盖。第二次 pack 后：

| 位置 | 尺寸 |
|---|---|
| `configs/p1_emmc_JL_M101/bootlogo.bmp` | 100×432 |
| `pack_out/boot-resource/bootlogo.bmp` | 100×432 |
| `h133-common` 默认 | 312×76（不要用） |

`boot-resource.fex` 从约 112K 变成约 169K，是竖图更大，正常。

## 5. 编译

```bash
source build/envsetup.sh
lunch h133-p1_emmc_JL_M101-tina
# 或
./tools/build_p1_emmc_JL_M101.sh full
```

只改 logo / 分区后不必重编 rootfs：

```bash
source build/envsetup.sh
p
```

产物：`out/h133_linux_p1_emmc_JL_M101_uart0.img`

本机 `nproc=18` 时 `m -j$(nproc)` 会把 host cmake 打挂（`read jobs pipe: Resource temporarily unavailable`）。rootfs 用 **`-j4`**。Tina 的 `m` 失败有时仍返回 0，以日志里 `build_openwrt_rootfs failed` 为准。

不要用 `./build.sh openwrt_rootfs package/.../compile` 单编包：会重打 toolchain，出现空包名。继续 `source build/envsetup.sh` 之后的 `m`。

编 rootfs 时 wolfssl 的 `options.h` 可能被装成空模板、e2fsprogs install 阶段 `LD` 对不上 `-Wl`。当时打过公共包补丁，**已按要求撤回**，不要合进板级。

| 检查 | 期望 |
|---|---|
| `.buildconfig` | `LICHEE_BOARD=p1_emmc_JL_M101`，`LICHEE_FLASH=default` |
| 内核 dts | `lcd_driver_name=jl_m101_jd9365da`，`lcd_x=800` `lcd_y=1280`，`sdc2=okay`，`spi0=disabled` |
| `pack_out/boot-resource/bootlogo.bmp` | **100×432**，不是 312×76 |
| 肉眼 | MIPI 竖屏；开机 logo 竖图 |
