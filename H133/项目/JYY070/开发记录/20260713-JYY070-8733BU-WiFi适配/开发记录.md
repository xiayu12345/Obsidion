## 0. 当前结论（先看这个）

**日常编镜像不要再手跑编 ko 脚本。**  
`m` 时 `rtl8733bu-kmod` 会用 Tina `out/kernel/build` + 内核同款 Linaro 工具链，从 `src/` 编出 `8733bu.ko` 打进 rootfs。

```bash
# JYY070
./tools/build_p1_nor_JYY070.sh full   # 或 kernel → rootfs

# p1_nor_8733：lunch 切板后同样 ./build.sh kernel + m + p
# 两板共用 rtl8733bu-kmod；先编内核再 m，否则包编译会报 Module.symvers 缺失
```

| 对比 | 旧做法（会踩坑） | **现做法** |
|---|---|---|
| ko 来源 | `files/8733bu.ko` 预编译拷贝 | `Build/Compile` 现场编 |
| 与内核配套 | 靠人记得跑脚本，易忘 | 编 rootfs 时自动按当前 Tina 内核编 |
| AIC8800 | JYY070 bsp 曾误开 | bsp **不开**；走 8733BU |

## 1. 现象（当初板上表现）

JYY070 刷入带 desk + wifimanager 的固件后，**点 Auto-Wi-Fi** 时：

```
usbcore: registered new interface driver rtl8733bu
Unable to handle kernel paging request at virtual address 00001000
Modules linked in: 8733bu
PC is at v7_dma_inv_range+...
[<bf07d3fc>] (usb_read_port [8733bu]) ...
WERR: wpa_supplicant ... executed failed
```

| 阶段 | 表现 |
|---|---|
| `insmod 8733bu.ko` | ✅（`vermagic` 字符串也能过） |
| `wlan0` | ✅ |
| `wpa_supplicant` / open | ❌ DMA Oops |
| 当时 8733 参考板 | ✅（老内核 + 同一份预编译 ko 碰巧匹配） |

**不是脚本没加载成功，而是预编译 ko 与已重编过的内核 ABI 对不上。**

---

## 2. 软件栈（与 8733 对齐）

```
desk Auto-Wi-Fi
  → wifimanager-v2.0
  → load_wifi_modules.sh → insmod 8733bu.ko
  → wpa_supplicant -i wlan0
```

| 层 | 要求 |
|---|---|
| OpenWrt | `rtl8733bu-kmod`、`rtl8733bs-firmware`、`wifimanager-v2.0`；不开 `kmod-net-aic8800` |
| init | `wifi_type="8733bu"`（与 8733 target 同逻辑） |
| bsp | **勿** `CONFIG_AIC8800_WLAN_SUPPORT` |
| DTS wlan | 与 8733 一致（busnum / regon / hostwake） |

屏/触摸差异**不直接改 WiFi**；早期坑在「内核重编了，预编译 ko 没跟着变」。

---

## 3. 排查摘要

1. JYY070 vs 8733 的 OpenWrt WiFi 脚本/defconfig → **一致，排除**  
2. JYY070 bsp 曾带 AIC8800 → 去掉后 Oops **仍在**（须保持与 8733 一致、勿开 AIC）  
3. **根因**：`files/8733bu.ko` 按旧 `Module.symvers` 编；JYY070 为显示/触摸多次重编内核后，`vermagic` 仍可能写 `5.4.61`，但 DMA 路径已炸  
4. 附加：重编驱动时需 `MODULE_IMPORT_NS(VFS_internal_...)`，否则 modpost/运行异常  

对照实验（2026-07-14）：仅重编 8733 内核、仍塞旧预编译 ko，**不一定**立刻 Oops——说明「一重编内核必挂」不成立；但预编译路径仍不可靠。最终改为 **包内现场编**。

## 8. 维护铁律

1. **先内核后 rootfs**；`rtl8733bu-kmod` 绑 Tina `out/kernel/build`，不是 OpenWrt `LINUX_DIR(5.4.182)`。  
2. **不要**在 JYY070 / 8733 的 bsp 开 AIC8800。  
3. 两板共用同一 `rtl8733bu-kmod`；切板重编内核后再 `m`，会**各自**编出匹配当期内核的 ko，无需两套驱动树。  
4. 用户态以 `h133-p1_nor_8733` 为准；JYY070 差异只在显示/触摸/DTS。  
5. `WIFI_AUTO_ENABLE=0`；连网由 desk Auto-Wi-Fi 触发。
