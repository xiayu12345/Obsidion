## 1. 背景

GSL 触摸都从 **`gslx680new/gslX680.c`** 上报。芯片固件量程经常小于（或轴向不同于）LVGL/fb0。

| 层 | 谁决定 | 例（JYY070） |
|---|---|---|
| 芯片 raw | 固件 | 1024×600 |
| `ctp_screen_max` | DTS | 1024×600（revert/裁剪） |
| fb0 / LVGL | 显示 | 1280×800 |
| `ctp_report_max` | DTS | 1280×800（报给 evdev） |

`EVDEV_CALIBRATE=0`：LVGL 把 ABS 原样当像素。内核不映射则点偏。

### 1.1 放弃的方案

| 方案 | 不采用原因 |
|---|---|
| `board_ui.h` + 脚本 | DTS 再解析一遍、改共享 `evdev.c` |
| `EVDEV_CALIBRATE` 写死 MIN/MAX | 按板编 `liblvgl`；`getevent` 仍是芯片量程 |
| 改固件量程 | 维护成本高，Y 边界出过问题 |

---

## 2. 方案

在 `report_data()` 里：`exchange` / `revert` / 按 **`screen_max` 裁剪** 之后，再 `tp_map_to_report(screen → report)`；`input_set_abs_params` 用 report 范围。

### 2.1 DTS（可选）

| 属性 | 含义 |
|---|---|
| `ctp_screen_max_x/y` | 芯片物理范围；revert / 丢点仍用它 |
| `ctp_report_max_x/y` | 上报 userspace 的目标范围 |
| 未配或 0 | 等于 `ctp_screen_max_*`（恒等，其它板零影响） |

公式：`v' = v * report_max / screen_max`（相等则原样）。

### 2.2 坐标链路

```
芯片 raw
  → exchange / revert（按 screen_max）
  → 边界检查（超 screen_max 直接 return，不放大）
  → tp_map_to_report（screen_max → report_max）
  → input_report_abs → getevent / evdev / desk
```

### 2.3 各板怎么配

| 板 | screen_max | report_max | 效果 |
|---|---|---|---|
| **JYY070** | 1024×600 | 1280×800 | 放大，对齐 UI |
| **JL_M101** | 1280×800 | 1280×800 | 恒等；对齐 `disp_rotate=3` 的 LVGL，**不要**映回 fb 800×1280 |
| **ZS101** | 同京龙克隆 | 同左 | 触摸未单独立项；勿只改大 `report_max_x`（会只拉长 X） |

GT911 板不编这份驱动。

## 5. 新板

1. `ctp_screen_max` = 芯片量程（exchange 之后用于裁剪的轴）
2. `ctp_report_max` = LVGL 逻辑分辨率（与 `EVDEV_CALIBRATE=0` 对齐）
3. 两边相等 = 不缩放；只改大 `report_max`、`screen_max` 仍是 UI 尺寸 → 点会漂
