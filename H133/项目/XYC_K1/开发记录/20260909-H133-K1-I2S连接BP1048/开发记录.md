本记录说明 H133 I2S1 到 BP1048 的硬件连接、软件接入、现场排查过程。配套补丁覆盖：DTS 开 I2S1 播放并从机、ALSA 默认走 I2S、BP1048 UART。16bit MSB 对齐曾做过实验，无声后已回退，不要再改 I2S 驱动。

## 1. 硬件链路

播放链路：

`H133 I2S1 → BP1048B2 I2S 输入/DAC → 4558 运放 → AMP_LIN/AMP_RIN → HTA8128MTE → 喇叭`

| H133 | 网络 | 串联电阻 | BP1048方向 | 说明 |
|---|---|---|---|---|
| PG11 | I2S1-MCLK | R10005 33Ω | MCLK输入 | H133输出参考时钟 |
| PG12 | I2S1-LRCK | R10006 33Ω | 输出 | BP1048主机提供帧时钟 |
| PG13 | I2S1-BCLK | R10007 33Ω | 输出 | BP1048主机提供位时钟 |
| PG14 | I2S1-DIN0 | R10008 33Ω | I2S-DOUT | DSP到H133回采 |
| PG15 | I2S1-DOUT0 | R10009 33Ω | I2S-DIN | H133到DSP播放数据 |

BP1048的 DACL/DACR 经运放形成 `AMP_LIN/AMP_RIN`。功放 HTA8128MTE 的 ENA 受 BP1048 `MUTE` 网络控制，ENB默认上拉使能。现场确认 BP1048 开机播报有声，因此 DSP 电源、DAC、功放、喇叭链路正常。

### 1.1 IO电压

H133 PG组应配置为3.3V：

```dts
vcc-pg-supply = <&reg_pio3_3>;
```

理由：

- H133与BP1048之间只有33Ω串联电阻，没有电平转换。
- BP1048数据手册规定数字IO电源为3.3V。
- BP1048输入高电平门限 `VIH` 最低2.2V。

板端设备树与运行时 phandle 均已确认指向3.3V，配置值为3,300,000µV。

## 2. H133软件配置

I2S1设备树关键配置：

```dts
&i2s1_mach {
	soundcard-mach,format = "i2s";
	soundcard-mach,frame-master = <&i2s1_codec>;
	soundcard-mach,bitclock-master = <&i2s1_codec>;
	soundcard-mach,slot-num = <2>;
	soundcard-mach,slot-width = <32>;
	status = "okay";

	i2s1_cpu: soundcard-mach,cpu {
		sound-dai = <&i2s1_plat>;
		soundcard-mach,pll-fs = <1>;
		soundcard-mach,mclk-fs = <256>;
	};
};
```

含义：

- Philips I2S格式。
- H133的 BCLK/LRCK 均为输入，即H133为从机。
- 双声道、每声道32-bit slot。
- H133输出256fs MCLK。
- 播放数据通过PG15 DOUT0输出。

ALSA默认路由：

`pcm.!default → PlaybackI2S → hw:sndi2s1,0`

现场验证过 `hw:sndi2s1,0` 上 S16_LE、双声道、44.1kHz 播放。播放期间 PCM 为 `RUNNING`，`hw_ptr` 按 44.1k 递增。

UART3（PG0/PG1，1500000 8N1）现场已通：

- 查询版本 `AA 55 EC EF` 应答 `3F 11 H133-K1_XYC_MJ_V05 EF`
- DSP 心跳 `66 AA 00 EF`，电量满格 `AA A5 03 01 06 EF`
- 串口由 `dsp1048.sh` 守护进程常开，命令走 `/tmp/dsp1048.cmd`，RX 写 `/tmp/dsp1048.rx.bin`

## 3. 运行时验证

播放时关键寄存器：

```text
CTL=0x00000115
PG_CFG1=0x22222133
```

`CTL=0x115`表示：

- I2S全局使能。
- TX使能。
- DOUT0使能。
- Philips I2S模式。
- BCLK/LRCK方向为输入。

`PG_CFG1=0x22222133`表示PG11～PG15处于I2S功能。

停止播放后现场读到：

```text
CTL=0x00000011
PG_CFG1=0xfffff133
```

此时TX关闭，PG11～PG15进入 `io_disabled`。在这种状态测量PG12，示波器可能把浮空串扰误判为约563.6kHz、1.76V的异常波形。测量时必须保持PCM为 `RUNNING`。

44.1kHz、双声道、32-bit slot时理论波形：

| 信号 | 频率 |
|---|---|
| MCLK | 11.2896MHz（256fs） |
| BCLK | 2.8224MHz（44.1k × 2 × 32） |
| LRCK | 44.1kHz，周期约22.68µs |

48kHz时对应为 MCLK 12.288MHz、BCLK 3.072MHz、LRCK 48kHz。

## 4. 走过的弯路（不要再做）

### 4.1 把 And 模式当成切 I2S 输入

协议表里的 `AA A6 01 01 00 EF` 是 **And 产品模式**，不是“切 DSP 到 I2S 输入”。这份协议没有 I2S/SPDIF/光纤输入源命令。把 And 当切源下发，本机 DSP 固件不认，还可能异常重启。见第 5 节。

协议里也没有静音查询。解静音是 `AA A6 02 01 00 EF`，DSP 不回这条。

### 4.2 把 H133 配成 I2S 主机

排查初期 DTS 曾把 `frame-master` / `bitclock-master` 指到 `i2s1_cpu`，H133 往外打 BCLK/LRCK。硬件是 **BP1048 主机、H133 从机**，两边抢时钟。已改回从机，见第 2 节和第 7 节补丁 `0001`。

从机模式下 PCM 能 `RUNNING` 且 `hw_ptr` 按 44.1k 涨，说明 DSP 已在出 BCLK/LRCK。

### 4.3 16bit 放进 32bit slot 的 MSB

曾把 `snd_sunxi_i2s.c` 里 S16 播放的 `TXIM` 从 LSB 改成 MSB，怀疑 DSP 读到全 0。改完仍无声。用户要求回退，**源码已恢复原厂 `TXIM=1`（LSB）**。不要再改这一处。HDMI 非 PCM 那条 `TXIM=0` 是原厂代码，不要动。

## 5. DSP UART协议问题

原代码把协议表中的 `And模式` 解释成“I2S切换”，开机发送：

```text
AA A6 01 01 00 EF
```

现场确认此DSP固件不存在该I2S切换命令，发送会导致异常重启。该命令原来被发送两次：

1. `dsp1048.sh boot`
2. `desk_mcu_dsp1048_bootstrap()`

现已移除两处发送，同时删除无效的 `dsp1048.sh and` 子命令。开机只保留：

1. 启动并保持 `/dev/ttyS3` 守护进程，1500000波特率。
2. 发送解除静音。
3. 设置音乐音量。

AUX和蓝牙模式命令仍保留，因为现场可收到DSP模式应答。

## 6. 测试方法

### 6.1 查看软件状态

```sh
cat /proc/asound/cards
cat /etc/audio_output.mode
cat /proc/asound/card0/pcm0p/sub0/status
cat /proc/asound/card0/pcm0p/sub0/hw_params
```

期望：

- 声卡包含 `sndi2s1`。
- 输出模式为 `i2s`。
- 播放期间状态为 `RUNNING`。

### 6.2 直接播放

```sh
aplay -D hw:sndi2s1,0 test.wav
```

测试文件建议使用 S16_LE、双声道、44.1kHz。

### 6.3 示波器测量

必须在播放期间测量：

- PG11或R10005：MCLK。
- PG12或R10006：LRCK。
- PG13或R10007：BCLK。
- PG15或R10009：播放数据。

建议使用×10探头、短地弹簧、DC耦合。若DSP侧波形正常而H133侧异常，检查33Ω电阻、焊接和短路；若DSP侧也异常，检查DSP固件I2S主机配置。

## 8. 注意事项

- 不要再执行 `dsp1048.sh and`，修复后该子命令已删除。
- 不要直接以115200波特率向 `/dev/ttyS3` 发送旧 `AF 55` 协议。
- `/dev/ttyS3` 应由 `dsp1048.sh` 守护进程独占，命令通过 `/tmp/dsp1048.cmd` 发送。
- I2S静止时的浮空波形不能用于判断LRCK频率。
- H133侧运行正常不能单独证明DSP已按正确格式接收；最终以示波器波形和实际出声为准。
- 不要把 `snd_sunxi_i2s.c` 的 S16 `TXIM` 从 LSB 改成 MSB，实验无效且已回退。
