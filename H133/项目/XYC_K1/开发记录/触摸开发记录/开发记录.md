## 1. 背景

JL_M101 原方案是 **Silead GSL3670**（`allwinner,gslX680` @ `0x40`），TWI1 + PG2/PG3。H133-K1 硬件换成 **Betterlife BL3676**，I2C 脚位不变，从地址 **0x2C**。上机 `chipID = 41`。

桌面：`desk_huiyin`（`lv_port_indev_init` → `evdev_read`）。`setting.ini`：`disp_rotate=0`，`tp_rotate=0`。

「智能K歌」generated 仍写 `/usr/bin/sing_ktv`，`desk_subapp_launch()` **硬切** `/usr/bin/hy_app`。

定稿原则：**厂家驱动原样报点，不改 evdev 协议解析**（`TRACKING_ID` / `SYN_REPORT` / `scroll_limit`）。短按不灵时先查总线和节点，不要在 IRQ / 用户态加“修短按”逻辑。子应用与桌面双开 fd 造成的点穿，**不要**在 `liblvgl` 里 `EVIOCGRAB`，由应用自己挡（第 9 节）。

## 2. 硬件脚位（原理图 H133-K1）

| 信号 | 脚位 | 说明 |
|------|------|------|
| SCL / SDA | PG8 / PG9 | TWI1，400 kHz |
| RST | PG2 | 复位，驱动 `gpios[0]` |
| INT | PG3 | 中断，驱动 `gpios[1]`，**下降沿**有效 |
| 电源 | VCC-CTP1 | 3.3 V |
| I2C 地址 | 0x2C | 资料也可 0x3D / 0x4E，本板实测 0x2C |

## 3. 定稿做了什么

### 3.1 厂家驱动

路径：`kernel/linux-5.4/drivers/input/touchscreen/betterlife_ts/`

相对 `betterlife_ts.7z`：

| 项 | 厂家包 | 本工程（定稿） |
|----|--------|----------------|
| 芯片宏 | `TS_CHIP=BL7XX1`，`BTL_CHIP_NAME=BL3676`，`CTP_SLAVE_ADDR=0x2c` | 保持 |
| 协议 | Type A | 保持 |
| `uaccess.h` | `asm/uaccess.h` | `linux/uaccess.h`（5.4） |
| `fwbin[]` | `#error` 强制填固件 | 去掉 `#error`；空数组，模组自带 Flash |
| `btl_read_flash` | 先调用后定义 | `fw_update.c` 补前置声明 |
| 产测 | `factory_test/` | 未合入 |
| 充电 / APK / 自动升级 | 可开 | **关** |
| ESD / debugfs | 原厂模板可开 | **关** |
| 调试宏 | `BTL_DEBUG_SUPPORT` + `LogEn=1` | **关**（IRQ 热路径 `printk` 会堵 ONESHOT） |
| input 名 | `betterlife-ts` | **`betterlife-touch`**（`input_symlink.sh` 的 `*touch*` 才能链上） |
| IRQ | 每次中断只读一次 | **保持只读一次** |

`Kconfig` / 子目录 `Makefile` 为本工程新增。

### 3.2 内核配置

`device/config/chips/h133/configs/p1_nor_XYC_K1/openwrt/bsp_defconfig`（内核吃这份，**不是** `linux-5.4/config-5.4`）：

- `CONFIG_TOUCHSCREEN_BETTERLIFE_TS=y`
- `# CONFIG_TOUCHSCREEN_GSLX680NEW is not set`
- `CONFIG_EXTRA_FIRMWARE="gsl_firmware/gsl3670.bin"` **保留**（BL 不用它，删不删都不影响触摸）

编内核前若 `out/` 里 `.config` 仍是 GSL，必须先 `./build.sh loadconfig`。

### 3.3 DTS（TWI1）

本板 GSL 原方案就是 DMA。定稿保持 DMA，节点换成 BL：

```dts
&twi1 {
	clock-frequency = <400000>;
	pinctrl-0 = <&twi1_pins_a>;
	pinctrl-1 = <&twi1_pins_b>;
	pinctrl-names = "default", "sleep";
	/* TWI1 DMA 通道 44；本板实测可用 */
	twi_drv_used = <1>;
	dmas = <&dma 44>, <&dma 44>;
	dma-names = "tx", "rx";
	status = "okay";

	/* BL3676：gpios[0]=RST [1]=INT */
	betterlife_ts@2c {
		compatible = "BTL,betterlife_ts";
		reg = <0x2c>;
		status = "okay";
		gpios = <&pio PG 2 GPIO_ACTIVE_HIGH>,
			<&pio PG 3 GPIO_ACTIVE_HIGH>;
		TP_MAX_X = <1280>;
		TP_MAX_Y = <800>;
	};
};
```

- 节点名用 **`betterlife_ts@2c`**，不要 `ctp@2c`
- 不要给 BL 加 GSL 的 `ctp_report_max` / `revert` / `exchange`
- `gpios` 顺序不要对调

对照目录 `20260908-XYC_K1-BL3676触摸适配` 写 TWI1 申请不到 DMA 通道、必须 `twi_drv_used=0`。那是他们从 JYY070 克隆下来的情况。**本板从 JL_M101 改过来，原 DTS 就是 DMA 44，2026-09-10 上机 DMA 可用**，不要改成 CPU。

### 3.4 用户态

- `input_symlink.sh` 匹配加上 `*betterlife*`（设备名已含 `touch`，旧 rootfs 也能链 `/dev/input/touch`）
- **不改** 报点解析、`scroll_limit`、`PRESS_LOCK`
- `evdev_set_file()`：`open(..., O_CLOEXEC)`；`evdev_read()` 在 `evdev_fd < 0` 时回 REL
- **不在** `liblvgl` 里 `EVIOCGRAB`（第 9 节）；`liblvgl` `PKG_RELEASE` 现为 7

## 4. 厂家协议（以源码为准）

- 读 `TS_DATA_REG=0x01`，一次 **62 字节**
- 用 `btl_i2c_write_read`（repeated start），不要拆成写完 STOP 再读
- `touch_num = point_data[1] & 0x0f`；**`touch_num==0` 才整板抬手**
- `eventFlag`：0=DOWN，1=UP，2=MOVE，3=空槽
- Type A 下 **`EventFlag=Up` 是空操作**，不能当成整板抬手
- 空槽：`id==0x0f` 跳过；循环仍扫 `MAX_POINT_NUM`（10）
- X 掩码厂家是 `& 0x0f`（不要改成规格书 `& 0x3f`）
- IRQ：`IRQF_TRIGGER_FALLING | ONESHOT`；`BTL_THREADED_IRQ`
- 不要改成 `IRQF_TRIGGER_LOW`
- 不要在 probe 写 `LPM=ACTIVE`

## 5. 走过的弯路（不要再做）

| 做过 | 结果 |
|------|------|
| IRQ 里 INT 仍低则连读最多 8 次 | 不是定稿；厂家每次只读一次，XYC 能用的也是这样 |
| 开 ESD（每 3s 读 `0xf9`） | 定稿关掉 |
| `evdev`：`SYN_REPORT` 分帧、`TRACKING_ID>=0` 为按下 | 撤回；协议解析不改 |
| `scroll_limit=50`、热区 `PRESS_LOCK`、关桌面滚动 | 明确否定，已撤回 |
| `page_nav_stack` 里 `lv_indev_wait_release()` | 切页吞点击，已撤回；现用关 indev 100ms + `lv_indev_reset` |
| 子应用退出 `evdev_drop_pending_touch()` + `wait_release` | 已撤回 |
| 进子应用关桌面触摸 fd、回来再 `open` | 明确否定，已撤回 |
| `evdev_set_file()` 里 `LVGL_LAUNCHED_BY_DESK` → `EVIOCGRAB` | 09-10 用过。`hy_app` 再拉 `xyc_mix` 时报 `Device or resource busy`，已从 liblvgl 拿掉 |
| 节点写成 `ctp@2c` | 改成 `betterlife_ts@2c` |
| 强制 `twi_drv_used=0`（跟 XYC） | 本板 DMA 可用；定稿 DMA |
| Type B、`EventFlag=Up` 当整板抬手、I2C 拆 STOP、X 改 `& 0x3f` | 必须退回 |
| `IRQF_TRIGGER_LOW`、probe 写 `LPM=ACTIVE` | 必须退回 |
| DTS `tp_cal_points` / 驱动内四角标定 | 不要 |
| 在 WSL 源码树本地 `make` 出 `.o` | 不要 |

`BTL_DEBUG_SUPPORT` 开着会在 IRQ 热路径 `printk`，表现为点了没打印、松手后日志才刷。定稿关掉。

只改 `evdev.c`（打进 `liblvgl.so`）时：

```sh
  out/h133/p1_nor_XYC_K1/openwrt/build_dir/target/root-h133-p1_nor_XYC_K1 \
  out/h133/p1_nor_XYC_K1/openwrt/build_dir/target/root.orig-h133-p1_nor_XYC_K1 \
  out/h133/p1_nor_XYC_K1/openwrt/build_dir/target/root-h133-p1_nor_XYC_K1-tmp

  cp -a "$SO" "$d/usr/lib/liblvgl.so.1"
 done
./build.sh openwrt_rootfs target/install
./build.sh pack
```

`package/.../compile` 之后直接 `target/install` + `pack`，镜像里仍可能是旧 `liblvgl.so`。点穿规避在 `hy_app` / `huiyin_ktv` 里，编对应应用即可，不必为 grab 去拆 squashfs 搜 `EVIOCGRAB`。

## 9. 子应用退出点穿（当前：应用侧挡）

### 现象

桌面点「智能K歌」，点右上角退出。应回桌面，却立刻进系统设置。一次短按，不是长按、也不是点了两下。

退出坐标约 `1195, 88`，落在桌面右上角设置热区 `screen_7_btn_11`（`1033,4` 起，`244×111`）。

内核一次短按：`eventFlag:0`（DOWN）+ 同坐标 `eventFlag:2`（MOVE，约 118 ms 后）+ 空槽 `id:15, x:4095, y:4095`。厂家 Type A 正常报点。

### 根因

- 桌面 `desk_huiyin` 启动时 `open(/dev/input/touch)`，进子应用只暂停 LVGL（`g_lvgl_paused`），**fd 一直开着**。
- 子应用是 `fork` + `execl`，自己再 `lv_port_indev_init()` → 又 open 一次。Linux evdev **每个 open 一份事件拷贝**（无 `EVIOCGRAB` 则两边都收）。
- 子应用处理「退出」后进程退出；桌面恢复 LVGL 时把队列里同一坐标当成新点击，打中设置。
- GSL 时期同样双开 fd，但 GSL 抬手报 `TRACKING_ID=-1`，短按很快 Down→Up。BL3676 Type A **永远 id=0**，`evdev.c` 把 `TRACKING_ID==0` 当按下；抬手不报 `-1`，短按还会多一帧同坐标 MOVE。所以换芯片后才爆。
- 桌面拉子应用时已有 `setenv("LVGL_LAUNCHED_BY_DESK", "1", 1)`（`desk_subapp_mgr.c`），不必再改桌面启动逻辑。

### 09-10 曾用 liblvgl EVIOCGRAB（已撤）

当时做法：`evdev_set_file()` 见 `LVGL_LAUNCHED_BY_DESK` 就 `ioctl(EVIOCGRAB, 1)`，桌面 fd 一直开着但收不到点。

后来 `hy_app` 再 fork `xyc_mix`，两层都带这个环境变量，第二层 grab 失败：`EVIOCGRAB: Device or resource busy`。共享库级独占拿掉，改应用自己挡。

### 当前工程怎么挡

桌面仍是：进子应用 `g_lvgl_paused=1`（停 `lv_timer_handler`），触摸 fd 不关；回来再跑 LVGL。`web_touch_claim` 只把网页遥控切回桌面，跟物理 TP 点穿无关。

| 路径 | 做法 | 代码 |
|------|------|------|
| hy_app ← 嵌套子应用（xyc_mix） | 顶层铺全屏透明可点 obj，吃掉残留按下；`RELEASED` 后再等 100ms 拆，最多 500ms 超时；拆时 `lv_indev_reset` | `app/hy_app/src/launcher/lv_app_launcher.c` |
| hy_app / huiyin_ktv / sing_ktv 切页 | `lv_indev_enable(NULL, false)` + `lv_indev_reset`，100ms 后再开。**不是** `wait_release` | 各 `page_nav_stack.c` 的 `page_nav_block_input_temporarily` |
| huiyin_ktv → 桌面 | `huiyin_ktv_ui_shutdown()` 后 `sleep(1)` 再 `huiyin_app_request_exit()` | `huiyin_ui_nav.c` |
| hy_app → 桌面 | `sleep(1)` 已注释，直接 `boot_ui_request_exit()`。桌面**没有**对等挡板 | `hy_app/.../events_init.c` `HOME_btn_exit` |
| 卡拉 OK overlay（demo） | 自己 `ioctl(EVIOCGRAB)`，kiosk 路径，不是桌面子应用这条 | `hy_karaoke_demo_cli/src/ui_overlay.c` |

`evdev.c` 只留 `O_CLOEXEC` 和 `evdev_fd < 0` 回 REL。**不改** `TRACKING_ID` 判断、`scroll_limit`、`PRESS_LOCK`、驱动报点。
