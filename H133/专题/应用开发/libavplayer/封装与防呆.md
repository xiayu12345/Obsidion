# libavplayer 封装与防呆说明

记录这个播放器库的设计取舍，方便后续维护和别人接手。

## 1. 业务到底要什么

> 一个画面一个音轨，但有时画面那条自带音轨想替换掉，有时客户切伴唱也要替换。

拆开就是两件事：

1. **画面始终在播**（一路视频）。
2. **声音可换**：自带音轨 ↔ 外部 mp3（原唱/伴唱）。

所以模型定为「**一路视频（主） + 一路按需的外部音频**」，而不是把视频和音频对等看待。视频是主角、是时钟来源；音频是可替换的配件。

## 2. 为什么不开两个视频实例

老版本用「视频实例 + 音频实例」两个 TPlayer 做音频叠加；新版本禁止双视频实例。

本库的做法：

- 视频实例**只有一个**，永远存在。
- 音频实例是 `AUDIO_PLAYER` 类型（纯音频，不带画面），按需创建、按需启停。
- 「替换自带音轨」= 把视频静音（音量 0）+ 起一路外部音频。画面没断，只是不出声。

这样既满足「单画面」约束，又实现了音轨替换。

## 3. 切音频怎么对齐

`av_player_switch_audio()` 内部固定四步：

1. 读视频当前位置 `pos`（视频是主时钟）。
2. 暂停画面、停掉旧音频。
3. 新音频 `set_source → prepare（等就绪）→ seek(pos)`；视频也 `seek(pos)` 兜底。
4. 一起 `start`。

体验上是**极短停顿**而非严格无缝——这是和你确认过的取舍：实现稳、不依赖底层秒切能力。若以后要无缝，可在 `av_backend` 增加 `switch_track`（同文件多音轨用 `TPlayerSwitchAudio`）的能力，接口已为此留好抽象层。

## 4. 字幕：明确的红线

字幕（尤其你那套**两层叠加字幕**）**完全不在本库内**，库也不碰它。

- 库只提供 `av_player_get_position()`，返回画面时钟（毫秒）。
- 你现有的字幕渲染器照旧：起个定时器，周期性取这个位置去刷字幕即可。
- 这样换音频、seek、暂停时，字幕时钟自动跟着画面走，不需要为字幕做任何特殊适配。

一句话：**库管音画，字幕归你**。这是刻意的解耦，避免把应用层逻辑塞进播放内核。

## 5. 后端抽象：真实 / 模拟两套

`av_backend.h` 把「一个播放通道」抽象成统一接口，核心层 `av_player.c` 只面向它，不直接调 TPlayer。

- `av_backend_tplayer.c`：真实后端，贴着工程里已验证的 `ktv_player_wrapper` 调 TPlayer。用 `AV_HAVE_TPLAYER` 控制，只有目标平台编译。
- `av_backend_sim.c`：模拟后端，纯软件时钟，不依赖任何多媒体库。本机就能编译、跑例程、验证切音频/seek/位置逻辑。

好处：

- 逻辑（编排）和平台（TPlayer）解耦，编排 bug 在本机就能复现修掉。
- 没有屏幕、没有 SDK 的机器也能 review 和测。
- 真实后端缺失时 `av_player_init()` 直接返回 `AV_ERR_UNSUPPORTED`，不会偷偷降级或崩。

## 6. 接口防呆清单

做减法，只留业务真正要用的：

- 没有 `download/fetch/wait/stats` 这类与播放无关的东西。
- 没有暴露 TPlayer 句柄、状态机、内部代等底层细节。
- `play/stop/pause/resume/switch_audio/use_embedded_audio/seek/get_position/get_duration/set_volume/set_display_rect` —— 每个都对应一个明确的用户动作。
- 错误统一用 `av_err_t` + `av_err_str()`，不返回裸 int。
- 配置用 `av_config_t` + `av_player_init_config_default()`，新增字段不破坏调用方。

## 7. 与 lv_projector 量产代码的关系

本库是**独立新库**，不改动量产的 `ktv_player_ui.c` / `karaoke_demo`。

- 想用新封装的 app 链接 `libavplayer`。
- 量产 projector 继续用它自己的播放器代码，互不影响。
- 字幕渲染器（karaoke）可被任意一方复用，因为它只依赖「播放位置」这一个输入。
