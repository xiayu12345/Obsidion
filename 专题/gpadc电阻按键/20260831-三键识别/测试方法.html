GPADC 电阻按键 — 测试方法

串口或 adb，root。座子只接 J9536（KEY ADC），不要接旁边的 J9538（MIC）。一次只按一颗。

界面不会动：LVGL evdev 仍跳过 sunxi-gpadc，界面不动不算失败。只核 ADC 电压和 /dev/input 键码。

电压表按板件，不能混用：

板特征当前 DTS / 补丁
板甲RA22 未串进采样，电压偏低未打进当前镜像；要刷须改 keyN_vol 再编 kernel
板乙经 RA22，与原理图一致当前镜像、当前补丁

换板必须先做第 1 节，不要拿另一块的 mV 硬套。

0. 刷机后先确认 dtb

镜像：out/h133_linux_p1_nor_JL_M101_uart0_nor.img
编包：./tools/build_p1_nor_JL_M101.sh kernel 再 ./build.sh pack。

反编译核 &gpadc（当前板乙）：

应看到 key_cnt = <5>（或 <0x5>），key0_vol～key4_vol 为 207 / 291 / 335 / 373 / 533（十六进制约 0xcf / 0x123 / 0x14f / 0x175 / 0x215）。
键码：key0_val～key4_val = 164 / 165 / 163 / 114 / 115（0xa4 / 0xa5 / 0xa3 / 0x72 / 0x73）。

板甲镜像则应是 3 / 106 / 161 / 208 / 404。对不上就先别测键码，dtb 没打进这张图。

1. 读芯片脚电压（改表前、换板必做）

驱动 sysfs，单位 mV，就是 keyN_vol 该写的数。不要循环刷，按住一颗再读一次。

1.1 选通道（写一次即可）

通道 0 = GPADC0（原理图球 C11）。

1.2 空闲（没按）

应接近 1800。若远低于 1800 且没按键，座子可能一直被拉低（短路或接错）。

1.3 按住再读

按住第一档不松，再 cat；松手换下一档按住，再 cat。dmesg 同时会打 vol_data:，和 cat 同一数字。

读出来仍是 1800：没按住，或座子不是 J9536。

1.4 期望（电阻档位相同，两块板 ADC 不同）

电阻 → 功能（两块板一样）：

电阻功能键码
0Ω播放/暂停164
3.3k上一曲165
5.1k下一曲163
6.8k音量减114
15k音量加115

板甲（RA22 未串进采样）：

电阻cat /sys/class/gpadc/data
0Ω3
3.3k106
5.1k161
6.8k208
15k404
空闲~1800

板乙（经 RA22，当前 DTS）：

电阻cat /sys/class/gpadc/data
0Ω207
3.3k291
5.1k335
6.8k373
15k533
空闲~1800

允许和表差几十 mV（接触、线长），但档位必须能分开。板乙上 5.1k 与 6.8k 只差约 38mV，接触不稳会串档。

五颗都记下来，从小到大 写入 key0_vol…key4_vol。公式（RA22 串在座子外侧时）：

Vchip = 1.8 × (6.8k + R) / (51k + 6.8k + R)

keyN_vol 必须写 芯片脚 mV（本 sysfs），不是座子外侧万用表值。

2. 查 input 节点

应类似：

N: Name="sunxi-gpadc0"
...
H: Handlers=event1
B: KEY=...

Handlers= 里的 eventN 才是后面要 dump 的节点（常见 event1，号会变，以本机为准）。
KEY= 位图里应覆盖 114 / 115 / 163 / 164 / 165。

没有 sunxi-gpadc0：&gpadc 的 status 或 channel_select 没开，先查 dtb，不要 dump 别的 event。

3. hexdump 验收键码

镜像一般没有 evtest。用 hexdump；没有则用 od。

event1 换成第 2 节读到的号。没有 hexdump：

测完一颗 Ctrl+C。一次只按一颗，按一下立刻松，先看短按；长按另见第 4 节。

3.1 怎么读 16 字节包

32-bit 一包 16 字节。前 8 字节是时间戳，看后 8 字节：type(2) code(2) value(4)，小端。

短按播放/暂停（0Ω，码 164）典型两行：

xx xx xx xx xx xx xx xx  01 00 a4 00 01 00 00 00
xx xx xx xx xx xx xx xx  00 00 00 00 00 00 00 00
出现的字节含义
01 00EV_KEY
a4 00164 播放/暂停（0Ω）
a5 00165 上一曲（3.3k）
a3 00163 下一曲（5.1k）
72 00114 音量减（6.8k）
73 00115 音量加（15k）
value 01 00 00 00按下
02 00 00 00连发（长按，驱动开了 EV_REP）
00 00 00 00松开

下一行全 00（type=0 code=0 value=0）是 EV_SYN，不是松开。松开是再来一包 EV_KEY + 同一 code + value=0，后面再跟一条 SYN。

3.2 五档期望（电阻相同，两块板 hex 相同）

电阻功能按下应出现
0Ω播放/暂停01 00 a4 00 01 00 00 00
3.3k上一曲01 00 a5 00 01 00 00 00
5.1k下一曲01 00 a3 00 01 00 00 00
6.8k音量减01 00 72 00 01 00 00 00
15k音量加01 00 73 00 01 00 00 00

松手应出现同一 code、value 为 00 00 00 00。

须刷 含本板 keyN_vol 的 dtb 后再验。电压表错（板甲刷了板乙表，或反过来）会串档：例如板乙上 5.1k 出成音量减 72。

改了 keyN_val 后 hex 里的 code 会变，例如把播放改成 114，按下就是 72 00 不是 a4 00。

4. 长按（EV_REP）

按住不放约 1 秒以上：

  1. 先一包 value=1（按下）
  2. 接着一串 value=2（连发），code 不变
  3. 松手一包 value=0

这是驱动开了 EV_REP，不是配错。验收只确认：短按有 1 和 0；长按中间允许有 2。不要把连发包当成多按了几次。

5. 验收清单

按顺序做，前一项不过不要往后凑。

#做过
1空闲 cat /sys/class/gpadc/data~1800
2五档各按住读一次与第 1.4 节本板表一致（板乙 207/291/335/373/533，板甲 3/106/161/208/404）
3grep sunxi-gpadc0 /proc/bus/input/devices有节点，Handlers=eventN
4五档各短按一次 hexdump码分别为 a4 / a5 / a3 / 72 / 73，先 value=1 再 value=0
5任一档长按1 → 若干 2 → 0，code 不变
6界面不动是正常的，不算本项失败

6. 失败怎么判

现象先查
cat 一直 1800没按住；接了 J9538；echo 0 没选通道
空闲远低于 1800座子一直被拉低
没有 sunxi-gpadc0&gpadc 的 status / channel_select；dtb 是否这张镜像
完全没有 hexdump 包电压 ≥ 1.7V 被当没按；lowdata；接错座子
短地对地不是 164（a4）key0_vol/val 是否被覆盖；刷的是另一块板的电压表
A 键出成 B 键key_vol 没按从小到大；中点窗口重叠；板甲/板乙表混用；板乙 5.1k/6.8k 接触不稳
按下立刻松开higdata 低于该键电压
最高那颗永远没事件电压 ≥ 1.7V，或被钳成 1.8V
长按刷很多包正常，value=2 是 EV_REP

改 dts 后怎么写表见 如何修改.md。硬件约定与两套电压定稿见 开发记录.md。
