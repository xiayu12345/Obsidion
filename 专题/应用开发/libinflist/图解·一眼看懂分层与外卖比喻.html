面向第一次读 libinflist 的人。配合 数据流与协作.md（更细的时序图）一起看。

渲染 Mermaid 需要支持的预览器（VS Code 装 Markdown Preview Mermaid Support，或 GitHub 直接看）。

1. 一眼认出「这是哪一层」

文件名前缀就是层，不用猜：

目录 / 文件层外卖比喻一句话职责
render/inflist_grid.*渲染层餐桌 + 服务员只摆「看得见的几个盘子」(cell)，滑动时复用，问上层要数据
text/inflist_text.*文字层主食柜按页缓存标题/副标题，缺页就喊「下单」
image/inflist_image.*图片层饮料柜按 id 缓存图片本地路径，缺图就喊「下单」
core/inflist_core.c + include/inflist.h协调层平台/前台把上面三层粘起来；对外只露 inflist.h
业务 App（不在库里）业务骑手 + 后厨真正用 libhttp_client 下载、用 cJSON 解析

记忆口诀：render 摆盘，text/image 两个柜子各管各的，core 是前台，下载是外包给骑手。

2. 关键：「一页多少条」在创建时传入，不用 ctx 指针

这是和老 cover 方案最大的区别，也是你直觉对的地方。

graph LR
    subgraph OLD["❌ 老 cover：每个请求 calloc 一个 ctx"]
        O1["发起下载<br/>calloc(ctx){page_size}"] --> O2["指针塞进 req.user_data"]
        O2 --> O3["回调里取出 ctx 读 page_size"]
        O3 --> O4["free(ctx)<br/>← 释放时机错了就 double free"]
    end
    subgraph NEW["✅ libinflist：创建时写死一次"]
        N1["inflist_open(cfg.page_size=50)"] --> N2["文字库内部记住 50"]
        N2 --> N3["解析任意页：id / 50 直接算<br/>无需随请求带指针"]
    end
    classDef bad fill:#8e2421,stroke:#3d0f0d,color:#fff;
    classDef good fill:#238636,stroke:#0b3b1b,color:#fff;
    class O1,O2,O3,O4 bad;
    class N1,N2,N3 good;

代码里就一处配置、一处使用：

  • 配置：inflist_cfg_t.page_size（inflist.h）
  • 使用：page = id / page_size; off = id % page_size;（inflist_text_db.c）

好处：没有「随请求生灭的小内存」，也就没有「谁 free、free 几次」的问题。代次失效靠 generation，不靠指针。

3. 外卖比喻（修正版完整流程）

你之前的比喻方向对，这里把两个反了的点改正：①点哪页由「餐桌」算，不是骑手；②摆盘(解析)在你家(UI线程)做，骑手只放柜+打电话。

sequenceDiagram
    autonumber
    participant U as 你(滑动)
    participant G as render 餐桌(UI线程)
    participant C as core 前台(UI线程)
    participant T as text 主食柜
    participant A as 业务(骑手/后厨)
    participant H as http worker线程
    participant TK as 定时器tick(UI线程)

    U->>G: 滑到看不见的位置
    G->>C: get_item(id) 要这条
    C->>T: inflist_text_get(id)
    alt 柜里有现货
        T-->>C: 标题/副标题
        C-->>G: 直接摆盘 ✅
    else 缺这一页
        Note over G,T: 餐桌自己算出缺第几页(id/page_size)
        T->>A: request_page(page, gen) 下单
        A->>H: http_download(json)
        Note over G: UI不卡，先摆占位
        H-->>A: 下好了(worker线程)
        A->>C: inflist_notify_page(...) 只打电话(投信)
        Note over C: 骑手到此为止，不进厨房
        TK->>A: tick取信 → parse_page 你自己摆盘(解析)
        A->>C: 逐条 commit_item(文字进主食柜, url进饮料柜)
        C->>G: 刷新这批 cell ✅
        C->>G: 顺便为可见区的图下单(request_image)
    end

退单/换店 = reset：代次 gen++。在途的旧外卖回来时单号(gen)对不上，直接扔掉，不会摆到新桌上 → 这就是不崩的根本。

4. 思维导图总览

mindmap
  root((libinflist))
    一眼分层
      render=餐桌(只摆可见cell)
      text=主食柜(按页缓存)
      image=饮料柜(按id缓存)
      core=前台(粘合·单例·只露inflist.h)
    page_size
      创建时传一次(cfg)
      解析用 id/page_size
      不再每请求calloc-ctx
    不崩三招
      静态收件箱(跨线程只投信)
      generation(旧结果丢弃)
      UI线程独写(无并发写)
    下载
      库自己不下载
      回调甩给业务+libhttp_client

5. 三句话记住

  1. 分层看前缀：render 摆盘、text/image 两个独立柜、core 前台。
  2. page_size 创建时给一次，解析靠 id / page_size，不用 ctx 指针。
  3. 回调只投信、解析在 UI 线程、代次丢旧货——这三条让 reset/close 永不野指针。
