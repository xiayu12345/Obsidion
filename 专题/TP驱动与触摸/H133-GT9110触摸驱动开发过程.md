## 2. 背景与目标

### 2.1 硬件变更

| 阶段 | 触摸 IC | I2C 地址 | 说明 |
|------|---------|----------|------|
| 早期备份（TP-H10） | **GSL** `gslX680` | **0x40** | `mtk_gslX680.bin` 固件，TWI1 @ PG8/PG9 |
| 当前（拓步 10.1 / 12.1 等） | **GT9110** | **0x14**（默认） | 无独立 `.bin`，用驱动内 **Config 组** |

主板 CTP 走线（与备份一致，**未因换 IC 改线**）：

| 信号 | SoC 引脚 |
|------|----------|
| I2C | **TWI1**，PG8=SCL，PG9=SDA |
| INT | **PG3** |
| RST | **PG2** |

### 2.2 软件目标

1. 内核 probe 成功，`/dev/input/event*` 有 **`gt9xxnew_ts`**；
2. 分辨率与屏一致：**物理竖屏 800×1280**（DTS + Config）；应用层可按产品选 **1280×800 逻辑横屏**（见 §7）；
3. I2C 地址按规格书 **默认 0x14**（复位时 INT 为高 → 8 位写 **0x28**）；
4. LVGL 通过 **evdev ABS** 读触摸，可与 USB 鼠标并存。

## 3. 驱动选型（为何用 gt9xxnew）

工程内核中存在 **两套** Goodix 触摸实现：

| 方案 | 路径 | 绑定方式 | 本板 |
|------|------|----------|------|
| **全志 BSP（选用）** | `gt9xxnew/` | `compatible = "allwinner,goodix"` + `init-input` 解析 `ctp_*` | **是** |
| 上游 Linux | `goodix.c` | `goodix,gt9110` 标准 OF | 否（无全志 `ctp_*` 流程） |

`gt9xxnew` 已内置 **GT9110** 配置名（如 `gt9110_wt097`、`gt9110_g200`），复位时 **I2C 地址选择** 与规格书 §6.1 一致（`gtp_reset_guitar()`）。

探测地址表（驱动内）：

```c
static const unsigned short normal_i2c[3] = {0x14, 0x5d, I2C_CLIENT_END};
```

## 4. 开发过程（分阶段）

### 阶段 A：调研与规格对齐

1. 阅读 [`GT9110-Datasheet_20121205.pdf`](../../硬件资料/GT9110-Datasheet_20121205.pdf)：
   - I2C ≤ **400kHz**（与 `board.dts` `clock-frequency = <400000>` 一致）；
   - 地址 **0x28/0x29**（7bit **0x14**）或 **0xBA/0xBB**（7bit **0x5d**），上电由 RST+INT 时序选定；
   - 配置寄存器 **0x8048~0x804B** 为 X/Y 最大值。
2. 确认工程已有 `gt9xxnew`，T113 等 defconfig 默认 `CONFIG_TOUCHSCREEN_GT9XXNEW_TS=y`。
3. 整理对照表 → [`GT9110-规格书要点与驱动对照.md`](../../硬件资料/GT9110-规格书要点与驱动对照.md)。

### 阶段 B：内核与设备树

#### B.1 `bsp_defconfig`

文件：`device/config/chips/h133/configs/p1_nor/openwrt/bsp_defconfig`

| 操作 | 配置项 |
|------|--------|
| 关闭 GSL | `# CONFIG_TOUCHSCREEN_GSLX680NEW is not set` |
| 去掉 GSL 固件 | `# CONFIG_EXTRA_FIRMWARE is not set` |
| 开启 GT9 | `CONFIG_TOUCHSCREEN_GT9XXNEW_TS=y` |
| 保持 | `CONFIG_INPUT_SENSORINIT=y`、`CONFIG_INPUT_TOUCHSCREEN=y` |

#### B.2 `board.dts`

文件：`device/config/chips/h133/configs/p1_nor/linux-5.4/board.dts`，节点在 **`&twi1`** 下：

```dts
/* GT9110: I2C 0x28/0x29 (7bit 0x14), INT high @ reset per datasheet default */
ctp@14 {
	compatible = "allwinner,goodix";
	device_type = "ctp";
	reg = <0x14>;
	status = "okay";
	ctp_name = "gt9xxnew_ts";
	ctp_twi_id = <0x1>;
	ctp_twi_addr = <0x14>;
	ctp_screen_max_x = <0x320>;   /* 800 */
	ctp_screen_max_y = <0x500>;   /* 1280 */
	ctp_revert_x_flag = <0x0>;
	ctp_revert_y_flag = <0x0>;
	ctp_exchange_x_y_flag = <0x0>;
	ctp_int_port = <&pio PG 3 GPIO_ACTIVE_HIGH>;
	ctp_wakeup = <&pio PG 2 GPIO_ACTIVE_HIGH>;
};
```

**注意**：勿再 enable `&twi2` 下旧模板 `ctp@14`（PB8/PB9），避免与 PG2/PG3 冲突。

#### B.3 触摸配置组 `gt9xx.h`

文件：`kernel/linux-5.4/drivers/input/touchscreen/gt9xxnew/gt9xx.h`

- 默认 **`ctp_name = "gt9xxnew_ts"`** 使用 **`CTP_CFG_GROUP1`**；
- 将 Config 中分辨率改为 **800×1280**（对应寄存器 0x8048~0x804B，小端）：
  - X：`0x20, 0x03` → 0x0320 = 800
  - Y：`0x00, 0x05` → 0x0500 = 1280
- `GTP_INT_TRIGGER = 0`：上升沿（规格书默认 00）；
- 校验和由驱动 `gtp_send_cfg` 前 **自动重算**，无需手改末尾 checksum。

若屏厂提供专用 `.cfg`，可新增 `ctp_name`（如 `gt9110_xxx`）并在 `gt9xx.c` 的 `config_info.name` 分支映射到对应 `CTP_CFG_GROUPx`（参考已有 `gt9110_wt097` / `gt9110_g200`）。

#### B.4 编译

```bash
# 工程根目录，改 DTS/内核后至少：
./build.sh kernel
./build.sh          # 或 platform 仅编 lv_projector
```

烧录：`out/h133_linux_p1_nor_uart0_nor.img`（以实际产物为准）。

### 阶段 C：板上内核验证

```bash
# 1) I2C：默认应为 0x14，显示 UU 表示驱动已绑定
i2cdetect -y 1

# 2) 驱动与 input 设备名
dmesg | grep -iE 'gt9|GTP|goodix|Guitar'
cat /proc/bus/input/devices | grep -A8 gt9xx

# 3) 原始事件（先停占设备的应用）
killall lv_projector lv_tp_test 2>/dev/null
getevent -p                    # 找带 ABS 的节点
getevent /dev/input/eventN     # 摸屏看 ABS_MT_POSITION_X/Y
```

**期望：**

- `i2cdetect -y 1` 在 **0x14** 为 **UU**（若只见 **0x5d**，改 DTS 为 `0x5d` 并确认复位时 INT 为低）；
- `dmesg` 有 `Guitar reset`、`gt9xxnew_ts` 注册成功；
- `getevent` 有 `BTN_TOUCH` / `ABS_MT_POSITION_*`。

### 阶段 D：LVGL / evdev 对接

#### D.1 `evdev_touch_init()`

文件：`platform/thirdparty/gui/lvgl-8/lv_drivers/indev/evdev.c`

逻辑：

1. 若存在 `/dev/input/touchscreen` 则优先打开；
2. 否则扫描 `event0`…`event15`，检测 **ABS_MT** 或 **ABS_X**；
3. 设备名含 **`gt9xx`** 优先绑定。

启动 log 示例：`evdev touch opened: /dev/input/event3`

#### D.2 `lv_projector`

文件：

- `lv_projector/src/main.c`：`indev_touch_drv` + `evdev_read`（POINTER）；
- `lv_projector/src/lv_drv_conf.h`：`EVDEV_SWAP_AXES=0`，`EVDEV_CALIBRATE=0`。

可与 USB 鼠标并存，详见 [H133-USB鼠标与GT911触摸并存-lvgl.md](./H133-USB鼠标与GT911触摸并存-lvgl.md)。

#### D.3 专用测试程序 `lv_tp_test`

拓步 10.1 阶段用 **`lv_tp_test`** 白底画点验证坐标，流程见 [tuopu-10.1-h133-tp-lvgl](./tuopu-10.1-h133-tp-lvgl拓步%2010.1%20寸%20TP%20开发与%20LVGL%20坐标映射.md)。

## 5. 软件架构（GT9110 实施后）

```text
┌─────────────────────────────────────────────────────────────┐
│ 应用：lv_projector / lv_tp_test                             │
│   · 触摸：evdev_read ← gt9xxnew_ts (ABS_MT)                 │
│   · 可选：evdev_read_mouse ← USB HID                        │
├─────────────────────────────────────────────────────────────┤
│ /dev/input/eventN                                           │
├─────────────────────────────────────────────────────────────┤
│ gt9xxnew_ts (gt9xx.c)                                       │
│   · gtp_reset_guitar() 选 I2C 地址                          │
│   · 下发 CTP_CFG_GROUP1（800×1280）                         │
│   · input_register_device("gt9xxnew_ts")                    │
├─────────────────────────────────────────────────────────────┤
│ init-input.c ← board.dts ctp@14                             │
├─────────────────────────────────────────────────────────────┤
│ sunxi-twi1 (PG8/PG9) ──► GT9110 @ 0x14                      │
└─────────────────────────────────────────────────────────────┘
```

## 7. 坐标与分辨率说明（易混点）

| 层级 | 典型取值 | 说明 |
|------|----------|------|
| 物理 LCD | **800×1280** 竖屏 | `board.dts` `ctp_screen_max_x/y` |
| GT911 Config | **800×1280** | `CTP_CFG_GROUP1` 字节 |
| 芯片实际上报 | 常见 **0~1279 × 0~799** | 横屏逻辑 **1280×800**，与拓步 UI 一致 |
| LVGL `lv_tp_test` | **1280×800** + sunxifb 90° | 仅 fb 旋转，**勿**再开 `disp_drv.rotated` 叠转 |
| GSL 时代 | DTS 曾写 1280×800 交换 | **已废弃**，GT9 勿照搬 GSL 的 swap 写法 |

若触摸与画面对不齐：

1. 用 `getevent` 看 raw 范围；
2. 调 `ctp_exchange_x_y_flag` / `ctp_revert_x/y_flag`；
3. 或 Config 里 **X2Y**（0x804D）与 `EVDEV_SWAP_AXES`（仅应用层）二选一，避免双重交换。

双显 + MIPI 软转见：[H133-双显-LVGL软转实践总结.md](../HDMI&mipi&lvds/H133-双显-LVGL软转实践总结.md)。

## 8. 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| `i2cdetect` 无 0x14/0x5d | 供电、FPC、TWI 引脚错（非 PG8/9） | 对原理图；测 3.3V |
| 地址是 **0x5d** 而非 0x14 | 模组 RST/INT 时序选低地址 | DTS 改 `0x5d` |
| `dmesg` 无 gt9 | 未编进内核、DTS `status` 非 okay | 查 `bsp_defconfig`、重编 kernel |
| probe 失败 / Config invalid | Config 组与屏不匹配 | 向屏厂要 `.cfg` 或换 `gt9110_*` 组 |
| 有驱动无坐标 | INT 边沿反了 | 改 `GTP_INT_TRIGGER` 或 0x804D |
| LVGL 无触摸 | 未走 `evdev_read`、节点被占用 | `evdev_touch_init` log；`killall` 再测 |
| 触摸与画面错位 | 双重旋转或 XY 重复交换 | 见 §7；对照 tuopu 文档 |
| 与 GSL 混用 | 仍加载 `gsl_firmware` | 确认 GSL Kconfig 与固件已关 |
