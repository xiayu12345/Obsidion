## 1. 硬件与接口（TP-H10）

### 1.1 本板 CTP 走线（与备份一致）

原理图 **CTP** 接 SoC **TWI1**（注释见 `board.dts`：`PG8` = CTP-SCK，`PG9` = CTP-SDA）。**不要**与 `twi2`（`PC0/PC1`）或旧 demo 的 `PB8/PB9` 混淆。

| 信号 | 备份 DTS（已调通） | 说明 |
|------|-------------------|------|
| I2C 总线 | **twi1**，`ctp_twi_id = <1>` | 用户空间 `i2cdetect -y 1` |
| I2C 地址 | **0x40** | GSL 系列常见地址 |
| 中断 INT | **PG3** | `ctp_int_port` |
| 复位/唤醒 RST | **PG2** | `ctp_wakeup` |
| 触摸 IC | **Silead GSL**（驱动名 `gslX680`） | 非 GT9 |

### 1.2 与显示的关系

触摸与 LCD **独立**：显示走 `disp` / `default_lcd` / MIPI DSI；触摸走 **I2C + input 子系统**。出现「有背光无图」或「有图无触摸」时，应 **分开排查**（参见 [H133-MIPI-HDMI双显开发记录.md](./H133-MIPI-HDMI双显开发记录.md) §4.6）。

### 1.3 触摸有效区域

10.1 寸 MIPI 主屏为 **800×1280** 时，DTS 中应使用：

- `ctp_screen_max_x = <0x320>`（800）
- `ctp_screen_max_y = <0x500>`（1280）

旧模板里的 `0x1e0`（480）对应其它分辨率屏，**不能**直接用于本板竖屏。

## 2. 软件架构

```text
┌─────────────────────────────────────────────────────────────┐
│ 应用：lv_projector（evdev）、lv_ds（touch_dev）等            │
├─────────────────────────────────────────────────────────────┤
│ /dev/input/eventX  ←  EV_ABS / BTN_TOUCH / SYN_REPORT       │
├─────────────────────────────────────────────────────────────┤
│ 触摸 IC 驱动：gslx680new / gt9xxnew / focaltech_touch …      │
│   · 通过 ctp_name 加载固件（GSL）或内置配置（GT9）            │
│   · late_initcall 注册 i2c_driver                           │
├─────────────────────────────────────────────────────────────┤
│ init-input.c：读 board.dts ctp 节点，GPIO/IRQ/上电/分辨率     │
├─────────────────────────────────────────────────────────────┤
│ sunxi-twi（I2C）+ 设备树 ctp@xx 子节点                       │
└─────────────────────────────────────────────────────────────┘
         TWI1 (PG8/PG9) ──► GSL @ 0x40
```

### 2.1 关键路径（p1_nor）

| 层级 | 路径 |
|------|------|
| 板级 DTS | `device/config/chips/h133/configs/p1_nor/linux-5.4/board.dts` |
| 内核 BSP 片段 | `device/config/chips/h133/configs/p1_nor/openwrt/bsp_defconfig` |
| CTP 公共层 | `kernel/linux-5.4/drivers/input/init-input.c` |
| GSL 驱动 | `kernel/linux-5.4/drivers/input/touchscreen/gslx680new/` |
| GT9 驱动 | `kernel/linux-5.4/drivers/input/touchscreen/gt9xxnew/` |
| Focaltech | `kernel/linux-5.4/drivers/input/touchscreen/focaltech_touch/` |
| 电阻屏（本板未用） | `kernel/linux-5.4/drivers/input/touchscreen/sunxi-ts.c`，DTS `&rtp` |
| LVGL 触摸 | `platform/thirdparty/gui/lvgl-8/lv_drivers/indev/evdev.c` |

## 3. 本工程可选驱动一览

| 方案 | `compatible` | `ctp_name` / 模块名 | 内核配置 | 本板 |
|------|--------------|---------------------|----------|------|
| **GSL（推荐）** | `allwinner,gslX680` | `mtk_gslX680` → 固件 `gsl_firmware/mtk_gslX680.bin` | `CONFIG_TOUCHSCREEN_GSLX680NEW=y` | **备份已用** |
| Goodix GT9 / **GT9110** | `allwinner,goodix` | `gt9xxnew_ts` | `CONFIG_TOUCHSCREEN_GT9XXNEW_TS=y` | **当前拓步/12.1 方案**，见 [H133-GT9110触摸驱动开发过程.md](./H133-GT9110触摸驱动开发过程.md) |
| Focaltech | `focaltech,fts` | 标准 OF 属性 | `focaltech_touch` 相关 | `fts@38` 为备选模板 |
| 电阻屏 | `allwinner,sunxi-ts` | — | `CONFIG_TOUCHSCREEN_SUNXI=y` | `&rtp` 为 `disabled` |

驱动通过 **`ctp_name` 与 `compatible` 必须与芯片一致**；换 IC 时三者（硬件、DTS、Kconfig）一起改。

## 4. 设备树配置（以 GSL + TWI1 为例）

### 4.1 pinctrl：TWI1 引脚

备份（正确，TP-H10）：

```dts
twi1_pins_a: twi1@0 {
    pins = "PG8", "PG9";
    function = "twi1";
    drive-strength = <10>;
};
```

当前 `H133-02` 仍为 `PE14/PE15`，与原理图 **不符**，需改回 **PG8/PG9** 后再 enable `twi1`。

### 4.2 `&twi1` 与 `ctp` 子节点

备份参考（路径：`H133-备份/H133-20260306/device/config/chips/h133/configs/p1_nor/linux-5.4/board.dts`）：

```dts
&twi1 {
    clock-frequency = <400000>;
    pinctrl-0 = <&twi1_pins_a>;
    pinctrl-1 = <&twi1_pins_b>;
    pinctrl-names = "default", "sleep";
    twi_drv_used = <1>;
    dmas = <&dma 44>, <&dma 44>;
    dma-names = "tx", "rx";
    status = "okay";

    ctp@40 {
        compatible = "allwinner,gslX680";
        device_type = "ctp";
        reg = <0x40>;
        status = "okay";
        ctp_name = "mtk_gslX680";
        ctp_twi_id = <0x1>;
        ctp_twi_addr = <0x40>;
        ctp_screen_max_x = <0x320>;
        ctp_screen_max_y = <0x500>;
        ctp_revert_x_flag = <0x0>;
        ctp_revert_y_flag = <0x0>;
        ctp_exchange_x_y_flag = <0x0>;
        ctp_int_port = <&pio PG 3 GPIO_ACTIVE_HIGH>;
        ctp_wakeup = <&pio PG 2 GPIO_ACTIVE_HIGH>;
    };
};
```

### 4.3 禁用错误总线上的旧节点

当前工程在 **`&twi2`** 下仍保留 **GT9**（`0x14`，PB8/PB9）与 **Focaltech** 模板，且均为 `disabled`。对齐 TP-H10 后应：

- **`&twi2`**：`status = "disabled"`，并注释说明 CTP 不在此总线；
- 勿 enable 与 PG2/PG3 冲突的 GPIO 定义。

### 4.4 DTS 属性说明（`init-input.c` 解析）

| 属性 | 含义 |
|------|------|
| `status` | 必须为 `okay`，否则 `ctp_used = 0`，驱动直接退出 |
| `ctp_twi_id` | TWI 控制器编号（twi1 → 1） |
| `ctp_twi_addr` | 7 位 I2C 地址 |
| `ctp_name` | GSL 固件文件名（不含路径/后缀）：`gsl_firmware/<ctp_name>.bin` |
| `ctp_int_port` | 中断 GPIO |
| `ctp_wakeup` | 复位/唤醒 GPIO |
| `ctp_screen_max_x/y` | 逻辑坐标上限，与屏分辨率一致 |
| `ctp_revert_x/y_flag` | X/Y 镜像 |
| `ctp_exchange_x_y_flag` | X/Y 对调 |
| `ctp-supply` / `ctp_power_ldo` | 可选，触摸独立 LDO 时配置 |

## 5. 内核配置与固件

### 5.1 `bsp_defconfig`（备份 vs 当前）

| 配置项 | 备份（TP 正常） | 当前 H133-02 |
|--------|-----------------|--------------|
| `CONFIG_INPUT_SENSORINIT` | y | y |
| `CONFIG_TOUCHSCREEN_GSLX680NEW` | **y** | **未设置** |
| `CONFIG_TOUCHSCREEN_GT9XXNEW_TS` | 未设置 | 未设置 |
| `CONFIG_FW_LOADER` | y | 需与 GSL 同时打开 |
| `CONFIG_EXTRA_FIRMWARE` | `gsl_firmware/mtk_gslX680.bin` | 无 |
| `CONFIG_EXTRA_FIRMWARE_DIR` | 指向 rootfs `lib/firmware` | 无 |

修改 `device/config/chips/h133/configs/p1_nor/openwrt/bsp_defconfig` 后，须 **重新编译 kernel**（`build_p1_nor.sh full` 或 `./build.sh kernel` + `m` + `p`）。

### 5.2 GSL 固件

驱动加载逻辑（`gslx680new/gslX680.c`）：

```c
snprintf(fw_name, 128, "gsl_firmware/%s.bin", config_info.name);
request_firmware_direct(&fw, fw_name, config_info.dev);
```

要求：

1. 文件名为 **`mtk_gslX680.bin`**（与 `ctp_name` 一致）；
2. 放置路径（二选一或同时）：
   - 编进内核：`CONFIG_EXTRA_FIRMWARE` + `CONFIG_EXTRA_FIRMWARE_DIR`（备份指向 `openwrt/target/h133/h133-p1_nor/busybox-init-base-files/lib/firmware`）；
   - 或 rootfs：`/lib/firmware/gsl_firmware/mtk_gslX680.bin`。
3. 固件须由 **屏厂/模组厂** 提供，与玻璃、IC 型号、校准一致；**不能**用别家平台的表代替。

若仓库中暂无 `.bin`，可从 **备份工程编译产物** 或模组资料包中提取，再放入上述目录。

### 5.3 GT9 / Focaltech 简要说明

- **GT9**：`compatible = "allwinner,goodix"`，`ctp_name = "gt9xxnew_ts"`，驱动 `gt9xxnew/gt9xx.c`，同样依赖 `init-input`，`late_initcall` 注册。
- **Focaltech**：更偏标准 `focaltech,fts` 节点（`focaltech,reset-gpio` / `focaltech,irq-gpio`），与全志 `ctp_*` 命名并存时需只 enable 一套。

## 6. 开发流程（bring-up 清单）

### 6.1 硬件确认

1. 读原理图：TWI 号、SCL/SDA、INT、RST、供电。
2. 上电后 `i2cdetect -y <bus>`，确认从机地址（本板期望 **0x40**）。
3. 确认与 **耳机检测** 等复用：注释要求 **PG8 勿作 hp-det**。

### 6.2 修改设备树

1. 修正 `twi1_pins` → PG8/PG9。
2. 在 `&twi1` 下添加/恢复 `ctp@40`，`status = "okay"`。
3. 分辨率、翻转标志与 MIPI 方向一致。
4. 关闭 `twi2` 上错误 `ctp` 节点。

### 6.3 修改内核配置并编译

```bash
.cursor/skills/h133-build/scripts/build_p1_nor.sh full
```

改过 **DTS 或内核** 必须走 full；仅改 rootfs 且不动 boot 时可用 `rootfs` 目标。

### 6.4 板上验证

```bash
# 驱动与固件
dmesg | grep -iE 'ctp|gsl|gt9|goodix|firmware|input'

# I2C（twi1 一般为 bus 1，以 ctp_twi_id 为准）
i2cdetect -y 1

# input 设备
cat /proc/bus/input/devices

# 事件（安装 evtest 时）
evtest
# 或
getevent -lt
```

期望：

- 出现 **`gslX680`** 设备名；
- 触摸时有 `ABS_MT_POSITION_X/Y` 或 `ABS_X/Y` 事件；
- 坐标范围约 0～799 / 0～1279（竖屏）。

### 6.5 坐标与应用

- 坐标颠倒/镜像：只调 DTS 三个 flag 和 `ctp_screen_max_*`，**优先不要改应用**。
- 芯片量程 ≠ UI：`ctp_report_max_*` 内核线性缩放，见 [GSL触摸坐标映射](../开发记录/GSL触摸坐标映射/README.md)。
- **lv_projector**：`evdev.c` 按名称自动查找 **`gslX680`** 的 event 节点。
- **lv_ds**：配置项 `touch_dev`（如 `/dev/input/event0`），见 [LV_DS-双屏异显中间件架构.md](./LV_DS-双屏异显中间件架构.md)。

## 8. 常见问题速查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| `ctp is not used` / `ctp_used set to 0` | `ctp` 或 `twi` 节点 `status` 非 okay | 检查 DTS |
| `can not get fw from file gsl_firmware/...` | 未开 `FW_LOADER` / 无 `.bin` / `ctp_name` 错 | 补固件与 `bsp_defconfig` |
| `i2cdetect` 无 0x40 | TWI 引脚错、未 enable twi1、供电/复位 | 对照原理图与备份 DTS |
| 有 I2C 无触摸事件 | INT/RST 接错、固件与屏不匹配 | 换正确固件；查 GPIO |
| 坐标范围不对 / 飘移 | `ctp_screen_max_*` 或 revert/exchange 错 | 只改 DTS 坐标相关项 |
| 有显示无触摸 | 误查 LCD；触摸独立 I2C | 分开查 TP 与 `default_panel` |
| LVGL 无响应 | event 节点错 | `cat /proc/bus/input/devices`，确认 `gslX680` |

| 对比项 | `docs/硬件资料/TP` | H133-02 正式栈 |
